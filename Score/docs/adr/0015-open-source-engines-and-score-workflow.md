# 0015. 可替换音乐引擎与 Score 审阅工作流程

- 状态：提议
- 日期：2026-10-05

## 背景

AIlegro 已有自训练模型和连续演奏页面，Score 已有 v3.1 作曲与分析适配器。AMT 等代码和权重已下载，但不代表通过本机效果验证。开源工具覆盖生成、分析、转写、回放和导出，需要明确职责与接入边界，才能组成可以持续编辑的作品流程。

现有作曲结果按批次导入并审阅，默认清理目标范围、采用记谱量化。候选隔离、局部接受、文档基线冲突检查和后台作曲尚未完成。这些限制与是否换模型是分别需要解决的问题。

## 提议

- AIlegro 提供可替换生成引擎和实际能力报告；自有模型为基线，AMT 经验证后可成为任务引擎。Score 面板不直接调用模型或假定每个引擎支持全部任务。
- Score 负责选定和锁定材料、审阅候选、局部接受、撤销、记谱、回放与输出。候选采用临时预览文档，接受时才写回明确范围。
- 接口继续使用版本化 JSON。保留既有作曲契约；引擎能力和后台任务另有版本化协议，修改作曲语义时才引入新契约版本。
- 保存请求基线和锁定材料，写回前验证当前文档；过期或取消结果不覆盖用户修改。原始实际音高与精确时间保留，模型条件近似和输出量化不静默改写给定材料。
- 第三方库接在 browser / tools / adapter 边界，保持纯核心、自研排版和命令系统。六组乐器是主要控制对象，内部角色不形成重复操作栏。
- 运行模型固定权重版本；代码、权重和资源分别记录来源与许可。接受音乐与授权回流训练是不同操作。

## 后果

多个引擎可以使用同一套编辑和输出流程，也能分别保留失败结果而不牵动核心模型。但需要维护能力映射、候选状态、任务取消、精度预检和版本迁移；AMT 事件转换与本机推理仍需实验，尚不能承诺效果或速度。

该提议不取代 ADR 0002–0005、0008–0010 或 0014。新增训练条件通道若改变旧设计，另写具体模型 ADR；当前先沿用已有锁定约束和和声基线。

## 考虑过的其他方案

- 将 AIlegro 与 Score 合为一个实现：模型依赖与编辑器核心耦合，增加运行和演进成本。
- 只继续自训练、只把 AMT 当参考：会提前排除已经可用的条件生成引擎，缺少对照依据。
- 直接以第三方乐谱框架取代 Score：需迁移稳定 id、实际音高、命令和审阅语义；当前接入目标没有证明这种迁移必要。
- 未经对照就整体改用 AMT：会丢失已验证的控制和精确记谱行为，当前不能证明收益。

实施与验收见[Score 接入计划](../open-source-integration-plan.md)和[联合开发计划](../../../Compose/JOINT-DEVELOPMENT-PLAN.md)。
