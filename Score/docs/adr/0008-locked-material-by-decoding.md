# 0008. 生成区间内的给定材料：用 AIlegro 的解码约束实现，不重训模型

- 状态：已接受
- 日期：2026-10-02

## 背景

`accompany-melody`、`orchestrate`、`develop-motif` 要求在**要写的小节里**保留用户给定的音符（旋律、待配器的音乐）或
参照一个动机。AIlegro 四大件 v3.1 是逐事件因果生成：同一起音内先写和弦变化，再从低音往上写音符，模型只看已写下的
内容。v3.1 已训练完成（第 45,225 步），没有“给定材料”输入，`feed_bar()` 只能整小节给定。

## 决定

- 在 AIlegro 里新增解码层（`training/scripts/four_pillar_v31_tasks.py`，不改训练代码和权重），适配器 import 它：
  - **小节内锁定音**：给定音按 v3.1 的流顺序插入；模型自己提出的事件若排在下一个给定音之前就保留，否则视为
    “现在写给定音”。在给定音的起音上，模型选了给定声部的乐器组，或在别的组提出给定音的音高，也视为写给定音
    （否则被屏蔽的模型会把给定旋律抄进伴奏）。给定音逐音保持。
  - **为旋律配伴奏**：每小节写 N 份（默认 16），保留“给定旋律在模型看来最自然”的那份。
  - **配器**：给定音的乐器组和声部按模型后验选（音高、时值一并计入；模型自己在该处提出这个音时用它的选择），
    告诉模型要用哪些组；可加至多给定音一半的八度/同度叠置（`--doublings`）。
  - **动机发展**：用参考小节机制。重述用原小节；模进、截取、减值等把动机所在小节的整个织体变换后作为参考；
    倒影只变换动机声部，保留其下方的伴奏。每小节做了什么写进结果的 `warnings`。
- 契约 `compose-request/1` 不变（用户 2026-10-02 决定）：动机发展的变形顺序由适配器自动安排，面板暂不提供选择。
- `develop-motif` 的目标声部包含动机所在的声部（动机在上下文里，新小节接着写）。

## 后果

- 三项任务现在就能用训练好的 v3.1 运行，Score 端只改适配器、任务列表和请求构建里 develop-motif 的目标声部。
- 用 AIlegro 的评估脚本（`training/scripts/eval_four_pillar_v31_tasks.py`，训练集窗口）量过：
  - 配伴奏：直接锁旋律时旋律音与伴奏的半音冲突 25%，选 8 份 14%，选 32 份 8%（真实艺术歌曲 8%）；
    强拍和弦音 53% → 73% → 84%（真实 90%）；伴奏与旋律的同音/八度重叠 41% → 65% → 68%（真实 67%）；
    计算量与份数成正比。第一版解码会让伴奏把给定旋律原样抄一遍，当天发现并修正，以上是修正后的数。
  - 配器：给定音分到原曲用过的乐器组 71%，按上下文音区分配 66%，随机 35%。
  - 动机发展：完整织体的合成参考与原小节参考的相似度接近（0.51 对 0.57，不参考 0.06）；只给最高声部时明显变低。
- 和声仍是配伴奏的瓶颈：同时锁定人写的和弦，强拍和弦音 88%，冲突 11%（选 8 份 10%）。下一步可以另训一个
  “旋律 → 和弦”的配和声模型（AIlegro 侧），或在 v3.2 加给定材料通道。
- 这些都是解码约束，不是新训练出来的能力；音乐质量要靠试听判断。

## 考虑过的其他方案

- **v3.2：加“给定材料”通道并微调**：结构上更干净，但要重新训练，且三项任务现在就要。保留为后续方案。
- **按声部拆成独立模型（和声 / 旋律 / 伴奏）**：联合四轨模型取代 Harmony v2 + Melody v5 时，同一批事件上旋律 CE
  2.219 → 1.900、下一和弦 4.105 → 2.412；按声部拆会丢掉声部之间的相互条件。
- **小节内逐拍的粒子重采样**：比按小节挑选更细，但需要把逐事件的解码循环改成可复制的状态机，先不做。
- **外部模型（如 Anticipatory Music Transformer）**：以秒计时、没有调与和弦，接入精确记谱要再量化，只适合当对照。
