# 0002. 语义化乐谱模型

- 状态：已接受
- 日期：2026-10-01

## 背景

模型要同时服务：精确排版、回放、AIlegro 的输入（需要发声 MIDI、精确时间、乐器组、声部身份）、
AI 结果的导入与审阅、版本对比和实时协作。MuseScore 的模型以“小节内的段”为中心、
包含大量版面信息；MusicXML 以记谱为中心、时间是 divisions 整数。

## 决定

- 存**音乐语义**，版面由排版推导；版面提示是显式的可选字段。
- 每个元素有**稳定字符串 id**（`<前缀>_<随机>`），由命令调用方生成。
- 时间用**有理数**，单位全音符；事件锚定在小节上（小节 id + 小节内 offset）。
- **一个发声的音 = 一个事件**，可以跨小节线；小节线处的连线是推导出来的；
  刻意的连线用 `tieForward`。
- 存**实际音高**并带拼写（step、alter、octave）；移调乐器的记谱音高由音程推导。
- **隐式休止符**：空隙即休止。
- 全局小节列表（所有谱表共享小节线），内容按 `谱表 → 小节 → 声部（≤4）`。
- 和弦记号使用 AIlegro 的和弦性质 id。
- `source`（provenance）标记用户 / 导入 / AI 来源。

## 后果

- 导出给 AIlegro 很直接：发声音高、绝对时间、乐器组、声部身份都能直接得到。
- 改时值、改拍号（重新划分小节线）时音符的绝对位置不变，不会产生碎片化的连线音。
- 排版要负责把长事件切分成可读的记谱（按拍号规则），这部分复杂度集中在引擎里，有测试覆盖。
- 不支持“小节内各谱表不同拍号”（复拍子混用的极端现代音乐）；需要时另立 ADR。

## 考虑过的其他方案

- 直接用 MusicXML 作为内部模型：冗长、以记谱为中心、时间是整数 divisions，不适合编辑命令和 AI。
- 每个谱表独立的小节列表：灵活，但总谱里罕见，且让所有查询变复杂。
- 存记谱音高：移调乐器的 AI 输入、回放都要反复换算，容易出错。
