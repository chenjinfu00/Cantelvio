# 0006. `.ailegro.json`：规范化、逐事件一行、适合 git

- 状态：已接受
- 日期：2026-10-01

## 背景

乐谱要放进 git、能在 PR 里审阅、能做版本对比；也要能被人和 AI 直接阅读。
MuseScore 的 `.mscz` 是压缩包，`.mscx` / MusicXML 冗长且一个音符跨很多行。

## 决定

- 文件就是 `ScoreDoc` 的 JSON，带 `format: "ailegro-score"` 和 `version: 1`。
- **规范化**：键顺序固定，内容按总谱顺序和小节顺序排列；保存同一文档两次得到相同字节。
- **可读**：有理数写成 `"1/4"`，音高写成 `"C#4"`。
- **逐事件一行**：每个音符事件（以及连音、力度、谱号变化、和弦、速度、谱表、括号）一行，
  `git diff` 逐音显示修改。
- 版本规则：任何字段变化都要升 `version`，在 `io/json.ts` 写迁移、加测试、更新
  [score-model.md](../score-model.md)；读到更新版本的文件时报错。

## 后果

- 文件比压缩格式大（但 git 压缩存储，影响很小）。
- 手工编辑可行，但必须保持结构合法；打开时会校验。
- 语义化对比（按 id）可以在此基础上实现（`M3-HIST-02`）。

## 考虑过的其他方案

- MusicXML 作为主格式：互通性好，但不适合 diff，也装不下我们的 id 和来源信息（会作为导入/导出格式支持）。
- 二进制或压缩 JSON：小，但失去 git 可读性。
