# 0009. 配伴奏的和弦由单独训练的配和声模型给出

- 状态：已接受
- 日期：2026-10-03

## 背景

为旋律配伴奏时，和声是主要短板（[ADR 0008](0008-locked-material-by-decoding.md)）。v3.1 在同一拍里先写和弦变化、
再写音符，旋律音排在最后，所以模型选和弦时看不到这一拍的旋律，只能猜。每小节写多份再挑能补一部分，
锁定人写的和弦效果最好，但要求用户先写好和弦。

## 决定

- 在 AIlegro 里单独训练一个小的配和声模型（`training/scripts/harmonizer_v1.py`，约 87 万参数）：
  双向 transformer 编码器读完整段给定旋律和调号，在十六分音符网格上给出 v3.1 和弦表里的和弦，
  用 Viterbi 解码成每小节的和弦变化。训练数据是 OpenScore Lieder 的人声旋律和 AugmentedNet 和弦标注，
  按作品划分训练、验证、测试。
- 适配器在为旋律配伴奏、且没有给定和弦（不是 `chordMode: given`）时，先用它从给定旋律读出和弦，
  再把和弦和旋律一起锁定，让 v3.1 写伴奏（`--harmonizer auto|none|<路径>`，默认 `auto`）。
- 和弦随结果返回，导入为和弦记号（AI 建议），用户可以修改后用 `chordMode: given` 重新生成。
- 契约不变：结果里的和弦本来就是 `compose-result/1` 的一部分。

## 后果

- 冲突明显减少：三首旋律（每小节选 8 份）的半音冲突 12% → 6%，强拍和弦音 72% → 99%；真实艺术歌曲
  （AIlegro 测试集 60 首）冲突 19.5% → 14.3%。测试集上和弦与 AugmentedNet 逐拍完全一致 36.9%
  （只依据调号的规则配和声 27.7%）。
- 和声节奏偏密，伴奏的音更多；解码惩罚可以调。
- 这是按“给定什么、生成什么”的任务边界拆分：v3.1 仍是联合生成模型，配和声模型只做它做不到的
  “双向读给定材料”。以后的和声分析（读全部声部）、配器分配可以用同样的方式加小模型。

## 考虑过的其他方案

- **只靠 v3.1 每小节写多份再挑**：选 32 份时冲突降到 8%，但耗时与份数成正比，强拍和弦音仍只有 84%。
- **按声部拆成串行的独立模型（和声 → 旋律 → 低音 → 节奏）**：旧的 Harmony v2 + Melody v5 换成联合模型时，
  旋律 CE 2.219 → 1.900、下一和弦 CE 4.105 → 2.412；串行拆分会丢掉声部之间的相互条件。
- **在 v3.2 里加“给定材料”通道并微调**：结构更干净，但要重训主模型；配和声模型几十分钟就能训完、可以单独替换。
