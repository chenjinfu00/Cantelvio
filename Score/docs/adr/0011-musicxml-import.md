# 0011. MusicXML 导入：自写解析器，连音线合并成一个事件，调号取不移调声部

- 状态：已接受
- 日期：2026-10-03

## 背景

`M2-CORE-04` 要能打开别的软件（MuseScore、Sibelius、Finale、Dorico）导出的乐谱，以后 PDF 识谱
（Audiveris）和音频扒谱的结果也经过 MusicXML 进来。MusicXML 是**记谱**格式（每个音符都写成可见的符头，
跨小节的音拆开再用连音线连起来，声部属于整个乐器，移调乐器存记谱音高），而 ScoreDoc 是**语义**模型
（一个发声的音 = 一个事件，声部属于谱表，存实际音高，见 [ADR 0002](0002-score-model.md)）。
`packages/core` 必须保持纯净（不用 DOM、不用 Node API，依赖只有 immer）。

## 决定

- **自己写一个小的、不校验的 XML 解析器**（`io/xml.ts`，约 360 行：元素、属性、文本、CDATA，跳过注释、
  处理指令和 DOCTYPE，解码 5 个预定义实体和数字字符引用，按 BOM / 声明识别 UTF-8、UTF-16、Latin-1）。
  `.mxl` 用纯 TS 读 ZIP 目录（`io/zip.ts`），解压交给平台（浏览器 `DecompressionStream('deflate-raw')`，
  Node `zlib`），core 里没有平台代码。
- **整个和弦都连到紧接着的同音高和弦时，合并成一个事件**，也跨小节线；只连了部分音的保留 `tieForward`。
  导入后的乐谱和用户自己输入的一样，排版器再按小节线和拍子拆开画连音线。
- **乐谱调号取不移调声部的多数调号**；只有移调乐器时用它们换算成实际音高后的调号。各声部不一致时提示。
- 模型里没有的东西（歌词、房子、D.C./D.S.、滑音、无音高打击乐……）**从不静默丢弃**：
  每一类按次数汇总成一条英文提示，编辑器显示前两条。
- 导入结果是一份新的未保存文档，保存时另存为 `.ailegro.json`，从不写回 MusicXML。

## 后果

- 不加依赖，浏览器和 Node 用同一份代码；music21 语料库 654 个文件全部导入且通过结构校验
  （见 [musicxml-import.md](../musicxml-import.md)）。
- 合并连音线后，原文件里的记谱拆分（例如 3 拍的音写成二分加四分）丢失，由排版器按自己的规则重新拆分；
  用户看到的写法可能和原谱不同，但时值和回放完全一致，AIlegro 拿到的也是真实的音长。
- 自写解析器不读外部 DTD，不认识自定义实体（原样保留）；MusicXML 实际上不用它们。
- 提示是英文（core 不依赖界面语言），编辑器里原样显示。

## 考虑过的其他方案

- **用现成的库**（浏览器的 `DOMParser`、`fast-xml-parser`、`sax`）：`DOMParser` 在 Node 和 Worker 里没有，
  会把 core 绑到浏览器；第三方库违反“core 只依赖 immer”。MusicXML 只用到 XML 的一个小子集。
- **保留每个记谱音符为单独事件，用 `tieForward` 连起来**：最接近原谱，但违反“一个发声的音 = 一个事件”，
  回放、AIlegro 导出、编辑命令都要处理拆开的音；只在部分连音的和弦里这样做。
- **调号取第一个声部的**：第一个声部常常是移调乐器（单簧管、圆号），会得到错误的实际调。
