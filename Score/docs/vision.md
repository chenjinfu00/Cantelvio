# 产品愿景与特色功能

## 一句话

**Cantelvio Score 是一款网页打谱软件**：能像 Sibelius / MuseScore 一样写钢琴、室内乐和交响乐总谱，
同时是 **Cantelvio**（AI 作曲 / 续写 / 配器系统）的乐谱前端——人在这里写下的音乐和设定，
可以无损地交给 Cantelvio；Cantelvio 写出的音乐，也回到这里供人审阅、修改、接受或拒绝。

## 为谁做

1. **作曲者本人（项目所有者）**：用 Cantelvio 做续写、配器实验时，需要一个能准确记谱、
   能把“我要什么”说清楚的输入端，以及一个能看懂、能改的输出端。
2. **会打谱的音乐人**：熟悉 MuseScore / Sibelius 的键盘输入，希望在浏览器里直接工作，
   不装软件，文件能放进 git、能比较版本。
3. **AI 编程助手（Codex、Claude）**：项目会和 AI 一起开发；代码结构、文档和测试要让
   AI 能安全地接手任务（见 [AGENTS.md](../AGENTS.md)）。

## 核心能力（必须做好的基础）

- **准确的乐谱模型**：精确有理数时值、带拼写的实际音高、移调乐器、多声部、连音、拍号/调号
  变化、弱起小节。错一个音、错一拍都不可接受。
- **专业的排版**：SMuFL（Bravura）字形、按时值的横向间距、自动分行分页、总谱括号与连线、
  移调记谱。目标是“打印出来像真的乐谱”。
- **高效的输入**：沿用 MuseScore 的键盘习惯（N、1–8、A–G……），鼠标点选输入，
  以及文字记谱输入。
- **规模**：从钢琴独奏到双管编制交响乐（20+ 行谱表）。

## 四个特色功能

### 1. 为 Cantelvio 服务

- 乐谱可以导出为 Cantelvio 的**精确记谱记录**（`ailegro.score-record/1`，兼容 Cantelvio 训练数据
  的 classical-score-v1 读取器）。
- 在编辑器里描述一个**作曲任务**（续写、依和弦写旋律、为旋律配伴奏、动机发展、配器），
  指定小节范围、可用乐器组、和声方式、采样参数，生成 `ailegro.compose-request/1`。
- Cantelvio 的结果（`ailegro.compose-result/1`）以**蓝色建议音符**回到乐谱，按“每次生成”为单位
  接受或拒绝，可撤销；来源（模型、运行 id）记录在每个音符上（provenance）。
- 两种连接方式：本机适配服务器（编辑器里一键“直接生成”），或文件交换（导出请求 → 在 Cantelvio
  文件夹里运行脚本 → 导入结果）。详见 [ailegro-integration.md](ailegro-integration.md)。

### 2. 乐谱版本历史与对比

- 文件格式是**稳定排序、每个音符事件一行的 JSON**，`git diff` 能直接看出改了哪些音。
- 所有修改都是**可序列化的命令**，元素都有**稳定 id**——这让“语义化对比”（第 12 小节小提琴
  改了两个音、AI 加了 4 小节）成为可能，而不是逐行文本对比。
- 计划：编辑器内的版本时间线、两个版本的乐谱并排/叠加对比、按来源（人 / AI / 导入）着色。
  设计见 [collaboration-and-history.md](collaboration-and-history.md)。

### 3. 多人实时协作

- 同样建立在“命令 + 稳定 id”之上：每个人的编辑是一串命令，服务器排序、广播，
  客户端在冲突时重放（rebase）。命令是确定性的（id 由调用方生成），所以重放结果一致。
- 计划分阶段：先做“共享命令日志 + 在线状态（谁选中了哪里）”，再做离线合并。
  设计见 [collaboration-and-history.md](collaboration-and-history.md)。

### 4. 文字 / 代码式输入

- 类似 LilyPond 的紧凑文字记谱：`c4 d e f | g2 g | <c e g>1`，相对八度、时值延续、
  按调号解释音名、连音 `3{ }`、小节检查 `|`。
- 用途：快速输入、测试与示例、**让语言模型也能写乐谱**。语法见 [text-notation.md](text-notation.md)。

## 设计原则

1. **乐谱文档是唯一的事实来源**：排版、回放、导出、AI 输入全是从文档推导出来的。
2. **所有修改都走命令**：可撤销、可记录、可重放、可协作、可由 AI 产生。
3. **语义而非图形**：存的是音乐（音高、时值、结构），不是图形位置。
4. **精确**：时值用有理数，音高带拼写；浮点数只用于图形坐标和音频秒数。
5. **契约要有版本**：文件格式和 Cantelvio 接口改动必须升版本、写迁移、写测试、更新文档。
6. **中文优先、双语界面**：所有界面文字都有中文和英文。

## 暂不做（非目标，至少在 v1 之前）

- 吉他六线谱、鼓谱专用记法、古谱（纽姆记谱）。
- 完整的 MusicXML 双向兼容（会做导入/导出，但先保证核心模型正确）。
- 原生桌面应用（网页版先行；以后可用 Tauri/Electron 打包）。
- 在浏览器里运行 Cantelvio 模型（模型在 Cantelvio 的 Python 环境里跑）。
