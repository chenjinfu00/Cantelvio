# Cantelvio Score 的开源接入与联合工作流程

日期：2026-10-05。状态：实施计划；2026-10-05 首轮候选演示已实现，见[实际验证](demo-verification.md)。以下待办以路线图和验证记录为准。

Score 是 Cantelvio 的乐谱工作台：输入和校对材料、确定生成范围、审阅候选、接受音乐、继续修改，再回放和导出。生成引擎、数据整理和训练由相邻 Cantelvio 项目负责。共同目标、组件选择和阶段顺序见[联合开发计划](../../Compose/JOINT-DEVELOPMENT-PLAN.md)，第三方文件与许可见[完整资源清单](../../Compose/OPEN-SOURCE-INVENTORY.md)和[Score 第三方说明](third-party-notices.md)。

## 首个可交付场景

用户在 Score 写入或导入 8–16 小节旋律，校对后将其锁定，选择钢琴或目标乐器组，生成几个伴奏候选。试听后按小节或乐器接受，修改局部，再只生成选定的未锁定范围，最后保存 `.cantelvio.json` 并导出 MIDI / PDF；MusicXML 导出随后补齐。

| 步骤 | 已有基础 | 待补齐的行为 |
| --- | --- | --- |
| 输入材料 | 手动输入、MusicXML 导入；PDF / 录音后台导入接口 | 对识别结果校对与保留来源；真实导入工具的本机可用性验证 |
| 配置任务 | 五项任务、生成区间、材料和锁定条件、六组约束与目标映射 | 六组操作与具体声部对应清楚；现有乐谱哪些保留、哪些重写可见，不增加重复角色栏 |
| 运行生成 | v3.1 适配器、同步 `POST /compose`、文件交换 | 多引擎实际能力报告；后台作曲进度、取消、固定运行版本 |
| 审阅音乐 | 带来源的蓝色建议、整批接受或拒绝、撤销 | 候选暂存与切换、原谱对照、按小节 / 乐器接受；旧请求结果与当前乐谱的冲突处理 |
| 再编辑与输出 | 编辑命令、保存、SoundFont 回放、MIDI 与矢量 PDF 接入代码 | 音高和时间往返复验、MusicXML 导出、MIDI 大编制、命名版本与语义对比 |

2026-10-05 已实现候选隔离预览、原谱对照试听与按小节/声部接受，只有接受才替换原谱；时间按 `quantize: 'exact'` 导入。传统文件导入和分析仍是待审阅建议。生成尾音超出请求范围时在预览中结束并提示；局部范围切过延音或时间线条时拒绝并要求扩大范围。

## 编辑器与乐器操作

基础面板围绕“材料、范围、乐器、生成、候选”组织。六组沿用既有契约：`woodwinds`、`brass`、`percussion`、`keys`、`high_strings`、`low_strings`。每组显示对应声部、允许参与 / 关闭、音区、密度与音量；只有引擎明确支持的控制才开放。要求必须发声与允许参与单独表达，不把播放静音当作生成禁用。

低音、和声、旋律是可推导的分析信息或高级条件，不再规划成另一套必须操作的声部角色栏。可选和弦建议仍能编辑并重新提交。锁定范围应准确到声部和时间，已有材料、用户接受的材料和未接受候选有不同状态。中英文文案都说明“保留”和“重写”的具体范围。

候选试听从临时文档推导；保留原谱可随时切回。接受操作显示影响的小节和乐器，检查与用户编辑是否冲突，然后作为一个命令批次提交。跨范围延音、渐强渐弱、踏板和其他线条按完整对象处理；需要扩展范围时说明扩展边界，避免截断后形成无效乐谱。

局部重生成采用当前文档重新导出请求，保持未选范围和锁定材料；参考上下文与允许写入范围分开。命名版本在接受候选前后保存快照，之后提供语义对比。会话撤销可先用于首期流程，命名版本与比较面板随后完成。

## 服务与结果写回

现有契约的实际音高、四分音符分数时间、六组和来源语义保持；ScoreDoc 的时间单位仍为全音符，转换固定四倍关系，只在桥接处完成。生成服务不能直接写 ScoreDoc。所有结果转换成确定性编辑命令，原谱保存和回放继续从 ScoreDoc 推导。

新增协议分两层：服务层报告引擎能力、固定模型版本和运行状态；任务层包住已有作曲请求，管理任务 id、候选、进度、取消和错误。新服务协议有自己的版本号；若修改作曲条件或返回语义，再升级作曲契约。既有 `compose-request/1` 文件交换和 v3.1 客户端继续兼容。具体端点和 schema 在实现前定稿，本计划不把拟议端点写成现有 API。

发出请求时记录：文档 id、目标小节 / 声部稳定 id、请求 id、输入内容指纹、锁定材料快照、目标映射和基线版本。返回时重新检查目标与锁定范围是否变化；小节插删、声部删除、用户修改、停止或取消后到达的结果不能自动覆盖当前文档。必要时让用户以独立候选保留旧结果或重新请求。在线候选与分析已检查文档指纹，取消晚到结果不写入；离线文件导入仍只有目标映射，尚无完整基线与锁定材料词表精度预检。

能力报告要包含任务、控制、材料精度、编制限制和实际可用性。AMT 验证完成后才能显示对应任务；不能将 v3.1 的五项任务列表照搬给它。模型名与权重哈希随结果留存；更完整的运行记录可先在服务与候选管理层保存，新增持久化字段时遵守文件版本和迁移规则。

现有 PDF / 录音任务已有进度与取消接口；作曲目前仍同步返回。后台作曲另行实现，取消既停止可取消的推理工作，也使旧结果失效。连续演奏阶段接收有明确边界的片段，带序号与来源去重，提交完整片段后才能成为编辑内容；不把每个实时事件直接改写正在编辑的乐谱。

## 回放、排版与导出

SpessaSynth / MuseScore General 接在 `apps/web` 回放层；MIDI 复用 `core.buildPlayback`；PDF 复用自研 SVG，使用 svg2pdf.js / jsPDF 和嵌入的中文字体。Bravura 和当前实际音高模型继续使用。新依赖不进入纯核心包，第三方版本与许可随锁文件和 notices 维护。

先复验单音、八度、移调乐器、打击乐、倚音、连音、跨小节延音、速度变化和停止后的未来音符。比较 Score 实际事件、桥接结果、播放调度与导出 MIDI；抽样检查发声音高。最终播放音与谱中实际音高应一致，记谱移调只影响显示。

当前 MIDI 单端口最多支持 15 个有音高声部。为交响乐补齐多端口或其他兼容输出策略，避免静默合并不同音色；不能在实现和播放器兼容验证前宣称完整管弦乐 MIDI 已支持。MusicXML 导出用回读比较关键语义，声明无法保留的记号；PDF 检查页面尺寸、中文、矢量与复杂版面。多声部碰撞、增量排版、分谱与歌词归 Score 路线图，不混到模型训练任务里。

## 任务与顺序

| 顺序 | Score 任务 | 关联联合阶段 | 验收内容 |
| --- | --- | --- | --- |
| 1 | `M3-AI-01` 基线联调；`M3-AI-03` 六组与声部操作；`M3-AI-13` 基线 / 锁定 / 冲突检查 | J1 | 真模型请求往返；锁定材料精确保持；返回期间修改乐谱不会被覆盖 |
| 2 | `M3-AI-05` 候选比较；`M3-AI-06` 局部接受 | J1 | 原谱独立保留；候选切换、局部接受、拒绝与一次撤销真实跑通 |
| 3 | `M3-AI-11` 引擎能力；`M3-AI-12` 后台作曲和取消 | J2 | 与 Cantelvio 的已验证引擎联调；不支持的任务关闭；取消后的返回无写入效果 |
| 4 | `M3-AI-09` 分析接入扩展；`M3-HIST-01/02/03` 版本与对比；`M2-CORE-05/09` 导出 | J3 | 分析建议可修改；版本可恢复；MusicXML 与大编制 MIDI 语义验证 |
| 5 | `M3-AI-14` 连续片段接入；`M2-ENG-01/02` 增量排版和碰撞 | J4 | 不重复、不漏跨段延音；提交后可编辑；大谱面编辑耗时有实测 |
| 后续 | 分谱、歌词、完整作品编辑，之后协作和发布 | J5 | 编辑与输出完整作品；协作继续既有命令日志路线 |

回放、MIDI、PDF 的现有接入代码需要在 J1 联调时复验。以前的检查记录只覆盖当时提交状态，不能代替后续修改的验证。许可与运行来源任务 `M5-OPS-03` 随每项新引擎和资源接入完成。

首期演示应交付：同一段旋律的原谱、生成请求、带版本的候选结果、接受并修改后的乐谱、MIDI / PDF，以及锁定一致性、过期结果、取消和撤销记录。音乐质量仍需试听，代码测试通过不能替代判断。

## 实现范围和设计记录

本轮更新文档与任务顺序，没有实现新模型、候选管理、局部接受或异步作曲。架构提议见 [ADR 0015](adr/0015-open-source-engines-and-score-workflow.md)，不取代现有模型、排版、命令、锁定材料和分析契约 ADR。来源限制以资源清单为准；未接受建议或用户接受的音乐都不会因本计划自动进入训练。
