# AIlegro 联合四轨 Transformer（v1）设计

> 2026-09-27。状态：**已接入 App**。网页使用 `runs/joint-v1/structured/model.pt`，由 `scripts/export_joint_js.py` 导出为
> `../vendor/lib/joint-weights.js`，浏览器推理在 `../vendor/lib/joint-model.js`。旧的 Harmony v2 / Melody v5 与规则伴奏/低音
> 已从运行时移除，保存在 `../archive/pre-joint-runtime-20260927/`。
> 训练代码在 `training/scripts/`（`build_joint_*`、`joint_data.py`、`joint_model.py`、`train_joint.py`、`evaluate_joint.py`），
> 结果在 `training/runs/joint-v1/`。

## 1. 目标

把现在分开训练的和声模型、旋律模型，以及由规则生成的低音和伴奏节奏，合成一个一起训练的模型。模型同时处理四条轨：

| 轨 | 内容 | 现状（App） |
|---|---|---|
| R 节奏 | 伴奏在每个十六分位置的起音/延音（休止、延音、单音起音、多音起音） | 规则伴奏型 |
| H 和声 | 和弦何时换、换成什么（40 种类型 × 12 个根音，相对调） | Harmony v2（只有和弦序列，没有时间） |
| B 低音 | 低音线的音高和节奏 | 规则（根音五音、行进、推进、持续） |
| M 旋律 | 旋律音高和节奏 | Melody v5 |

联合训练的目的：让和声、低音、节奏和旋律之间的配合从数据中学出来，不再依靠事后的固定加分（旧的 affinity 反馈）。另外，把音乐结构作为先验写进网络，检验它能否在小数据下加快训练。

## 2. 已定的设计决策

| 决策 | 说明 |
|---|---|
| **生成顺序：每个十六分步按 R → H → B → M** | 不让任何一轨提前生成。"伴奏领先 k 小节、旋律最后生成、和声提前一小节"的方案已按用户决定去掉；预判未来交给注意力从上下文里学。每个 token 能看到所有轨之前的内容，以及同一步中排在它前面的轨。 |
| **保留低音轨** | Lieder 统计：和弦切换那一刻，低音基本由和弦加转位决定（55% 根音，39% 其他和弦音）。但 61% 的低音起音出现在同一个和弦中间，12% 是和弦外音，7% 的和弦切换时低音在做持续音或延留音。所以和弦 token 不带转位，转位由低音轨给出，两者不重复。 |
| **合成预训练 + Lieder 微调** | 合成数据完全来自项目现有的规则系统，Lieder 是 CC0 数据，不引入新的授权问题。 |

## 3. 数据

### 3.1 Lieder 四轨语料（`build_joint_lieder.py`）

- 来源：固定提交版本的 OpenScore Lieder（CC0）。读 MusicXML（`.mxl`）和语料自带的 AugmentedNet v1.9.1 自动罗马数字分析（`analysis_automatic.rntxt`，精确到拍，含局部调）。
- 四条轨都放在十六分音符网格上：
  - **M**：第一个声乐声部，同一时刻取最高音。
  - **B**：最低一行伴奏谱表里正在发声的最低音（最低音轮廓）。
  - **R**：其余伴奏音符（去掉低音线上的音）的起音数。
  - **H**：把分析里的罗马数字换成和弦音级集合，映射到 AIlegro 的 40 种和弦类型。
- **对齐**：AugmentedNet 把弱起小节记为 m1，music21 记为 0。所以按"小节号 / 小节号−1 / 顺序"三种映射，分别计算和弦音覆盖率，取最高的一种。覆盖率中位数 0.89；低于 0.6 的 49 首不用。
- **拍号**：放宽到 2/4、3/4、4/4、2/2、3/8、6/8、9/8、12/8、6/4、3/2 等（旧语料只用 3/4、4/4）。
- **切分**：sha256(歌曲目录) % 10：0 为验证集（与 Melody v5 的规则相同，可以直接对比），1 为测试集（这次新留出、不参与任何选择），其余为训练集。
- **结果**：1,131 首，其中训练 924、验证 111、测试 96（去掉覆盖率不足的后为 885 / 108 / 89）。共 64,067 小节、81 万个十六分步。旧旋律语料为 135 首。

### 3.2 合成语料（`build_joint_synthetic.py`）

- **A 类（4,800 条）**：旋律语法（`train_melody.make_phrase`）生成旋律和每小节一个的和弦；伴奏和低音用 App 自己的规划器 `src/planner.js`（冻结的 v91 `buildBarEvents`，即 Free 模式的逐段规划）按风格生成。
- **B 类（5,312 条）**：和声语法（`train_harmony.make_phrase`）生成和弦序列，随机分配和声节奏（半小节到两小节），伴奏同上；旋律标为未知，不计损失。
- 风格：pop / jazz / blues / classical / ambient / exploratory。随机移调，调式随语法。

### 3.3 窗口与编码（`joint_data.py`）

- 窗口由整小节组成，最长 128 步（4/4 为 8 小节），步幅约半个窗口。
- 参照调取窗口内出现最多的局部调。和弦根音、旋律和低音音高都相对参照调表示；局部调作为每步的控制量输入。
- token 表：
  - R：`PAD UNK 休止 延音 单音起音 多音起音`
  - H：`PAD UNK 延续 + 480 个和弦`（窗口第一步写出当前和弦）
  - B：`PAD UNK 休止 延音 起音+48 个音高`
  - M：`PAD UNK 休止 延音 起音+36 个音高`
  - 延音可以跨小节线，所以旋律可以写连音，这解决了 v5 的限制。
- 控制量：拍号、小节内位置、节拍层级（强拍 / 拍 / 八分 / 十六分）、乐句内第几小节（mod 8）、局部调、数据来源（合成 / Lieder）、风格、参照调式。

## 4. 网络结构（`joint_model.py`）

**StructuredJoint（结构化，约 158 万参数，d=96，4 层，6 头，FFN 256）**

1. **四个子网络。** 每层中，R/H/B/M 各有自己的 LayerNorm、Q/K/V/O 和 FFN 权重（也就是"低音层""节奏 transformer"），端到端一起训练。
2. **一次跨轨注意力。** 四条轨按时间优先交错排成 R0 H0 B0 M0 R1 …，普通的因果遮罩恰好等于上面的生成顺序。所以同一次注意力里既有轨内关系，也有跨轨关系。
3. **最新 token 直接注入。** 每个位置的输入里，直接加入其他轨中最新的已生成 token。例如低音预测 t+1 时，能看到 t+1 的新和弦。
4. **和弦特征。** R/H 看 t 时刻正在响的和弦；B/M 看 t+1 的和弦、是否刚换和弦、以及换和弦后已过的步数。
5. **节拍旋转位置编码。** 每个头的前 16 维按三组角度旋转：4 个时间频率、2 个拍相位谐波、2 个小节相位谐波。因此"上一小节同一位置""同一拍位"天然相似，任何拍号都成立。
6. **相对和弦的音高输出。** B/M 输出层除了普通的音高分数，还有 12 维"相对当前和弦根音的音程"分数。这样"弹根音""落在三音"这类规律在所有和弦之间共享。
7. **损失。** 四轨交叉熵加权求和（R 0.5，H/B/M 1.0），PAD/UNK 不计。

**FlatJoint（通用基线）**：同一交错序列、同样的控制量输入和同样的注意力可见范围；但只有一套权重，用可学习的绝对位置，没有节拍/和弦特征和相对和弦输出，结构全靠模型自己学。有两个规模：

- 与结构化模型同等计算量：d=96、4 层，52 万参数。
- 与结构化模型同等参数量：d=128、7 层、FFN 512，161 万参数。

**因果性测试**：`training/tests/joint-causality.test.py`。随机改动任意 token，检查所有排在它之前（含它本身）的预测完全不变，同时之后的预测会变。另外故意做了两种错误改动，确认测试会失败。

## 5. 训练（`train_joint.py`）

- AdamW（lr 1.5e-3，warmup 200，余弦衰减到 5%，wd 0.03），batch 16 个窗口，dropout 0.1（只在残差上）。
- 先用合成数据训练 800 步，再用 Lieder 训练 2,400 步，其中 15% 的 batch 回放合成数据。
- 每 200 步评估一次。按 Lieder 验证集的加权损失选检查点；测试集不参与。
- 所有模型的数据、步数和学习率计划完全相同，同时记录步数和实际训练秒数；每步耗时另由 `benchmark_joint.py` 逐个单独测量。
- `--resume`：每 200 步保存完整训练状态（模型、优化器、所有随机数状态），中断后续跑与不中断的结果逐位相同。

## 6. 评估（`evaluate_joint.py`）

1. 四轨交叉熵：Lieder 验证集（全量）和测试集（只报告，不做选择）。
2. **旋律对比 Melody v5**：在同一批验证作品上，比较每个音符事件（起音或休止开始）的条件音高交叉熵，即"已知这里开始一个新事件，它是哪个音"。新模型用 p(token)/(1−p(延音))。两个模型看到的信息不同：v5 能看到当前和下一个和弦；联合模型能看到到目前为止的四轨内容。报告时会说明这一点。
3. **和声对比 Harmony v2**：在同一批验证作品的换和弦位置上，比较下一个和弦（排除当前和弦后）的交叉熵和 top-1。v2 输入之前最多 24 个和弦及其转位（转位由低音推出），风格设为 classical。
4. 训练速度：结构化和两个通用基线的验证损失，分别对照步数和训练秒数。
5. MIDI 样例：自由生成；给定真实伴奏只生成旋律；同一窗口的真实原曲作为对照。

## 7. 已知限制

- Lieder 的和声标签是 AugmentedNet 自动分析，不是人工标注；低音取左手最低音，会把左手分解和弦的一部分也算作低音；三连音量化到十六分会有误差。
- 真实数据只有 19 世纪艺术歌曲。其他风格仍然来自合成规则，风格覆盖没有本质改善。
- 没有力度、速度和表情建模。旧模型的动机记忆和乐句时钟改为乐句位置控制量加节拍相位注意力，没有显式的动机特征。
- 预测交叉熵和训练曲线不等于听感，仍需试听。

## 9. App 接入（2026-09-27）

- **浏览器推理**：`vendor/lib/joint-model.js` 逐位置增量解码，每个位置只算一次并缓存 K/V。与 PyTorch 在三个真实验证窗口上逐 logit 对照，最大差 2.4×10⁻⁵（`tests/joint-model.test.js`）。权重为未量化的 float32。
- **上下文窗口**：与训练一致，最长 128 步。窗口满时，从至少 48 步之前的小节线重新开窗，按训练的编码方式重新编码这段上下文（参照调取开窗处的局部调，窗口第一步写出和弦和正在发声的音，低音/旋律的基准音取参照主音的八度），不在注意力里截断。风格改变时也重新开窗，使整个窗口使用同一个全局条件。
- **采样规则**（作用在模型分布上，不是训练结果）：
  - Hold：和声轨保持；节奏、低音、旋律照常生成。Every bar：每个强拍必须换一个新和弦，其余位置保持。Free：只在拍点上由模型决定是否换和弦，一个和弦最长两小节。
  - 温度分两步：是否发生新事件（换和弦、新音）按温度 1 从模型抽取，温度只改变选哪个和弦或哪个音（top-p 0.95）。原因见下。
  - 密度对伴奏和旋律的新音加一个小的偏置（0.5 为中性）。低音限制在 E1–D4，旋律在 A3–A5（保证任何窗口都能编码：基准音最多比最低音低 11 个半音，旋律只有 36 个音高 token）。
  - 编辑未来和弦：在该步固定和弦（和所选转位的低音音级），之前的步保持不变，之后全部重新生成。已排程到音频的低音/旋律若跨过小节线，重新生成时保持到已排定的结束位置。
  - 新时间线从起始和弦、主音低音和一个靠近 G4 的和弦音旋律开始。
- **为什么温度要分两步（实测）**：艺术歌曲条件下，从冷启动用普通温度 0.8 生成 12 小节（6 个种子），平均每小节 0.26 次换和弦、0.32 个旋律音，6 次中有 5 次出现连续 ≥4 小节没有任何换和弦或旋律音——持续/休止这类高频 token 在低温下吞掉了分布。改为两步采样后为每小节 1.11 次换和弦、1.81 个旋律音，6 次中 1 次。较长生成（48 小节×4 个种子）为每小节 1.22 次换和弦、3.01 个旋律音，与 Lieder 验证集的 1.30 和 2.88 接近。
- **合成风格**：exploratory 风格的训练乐句没有旋律（B 类语法），旋律轨在该条件下没有训练过，因此网页不提供。
- **速度**：在云端容器 CPU 的 Node 22 中，含周期性重新编码，一个 4/4 小节约 75 ms、3/4 约 50 ms，分成约 6 ms 的片段在播放之前完成。浏览器 4 倍 CPU 降速下连续播放无排程超时。
