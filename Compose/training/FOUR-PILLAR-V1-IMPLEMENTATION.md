# 四大件 v1：未部署网络与训练准备状态

**历史状态：四项能力的网络路径、精确事件契约和约束接口已接通；曾开始一轮 v1 全语料短程试训，但用户于 2026-09-30 结束进程并删除该轮 `state.pt`，没有替换网页权重。** 下一轮跨调／表现／动机方案见 [FOUR-PILLAR-V2-TRAINING.md](FOUR-PILLAR-V2-TRAINING.md)。这份文档说明可测试的 v1 结构，不是音乐质量结论。设计目标与严格验收门槛仍以 [FOUR-PILLAR-V1-SPEC.md](FOUR-PILLAR-V1-SPEC.md) 为准。

## 四项能力在代码中的位置

| 作曲能力 | 已实现的模型路径 | 来源/可见性边界 |
| --- | --- | --- |
| 和声 | 当前网页的完整 `StructuredJoint` 检查点严格加载并冻结；旧 R/H/B/M 四条轨的最后可见特征分别进入交叉注意力，不在入口处合成一条；兼容 H/M 权重块初始化新解码器；给定和弦以根音、类型、小节及精确小节内偏移编码；规划器输出和声锚点 | 旧四轨窗口只接受已完成过去及显式可见步数；没有可信对齐就用 `NO_PRIOR`，不能从目标小节伪造旧输入。用户硬锁定的和弦原样保留在 sidecar，规划器锚点不得覆盖它 |
| 复调 | 因果事件 Transformer 回馈已经写出的 token 和声部指针；动态声部表在已有身份和 `NEW_VOICE` 之间选择；同一时刻音符在完整 onset slice 后提交 | `four_pillar_v1_codec.py` 的声部指针只指向当前已登记声部，没有 32/64 声部硬上限；声部表的组/角色只在相应 token 写出后可见；同组同角色声部仍有不同的动态位置编码；给定旋律 token 与声部由硬锁保留 |
| 曲式 | 最近 32 小节的因果 FormPlanner 展望后续 4 小节；从已完成小节更新最多 8 段动机记忆；输出密度、音区、织体、调性方向、过去动机回归指针及音高/时值变形代理 | 目标小节摘要只作损失标签，不进入规划器条件；动机回归和变形是代理，不等于人工曲式分析 |
| 配器 | 生成声部/音符时使用六组、角色、音域和动态声部指针掩码；规划器输出组活动提案 | `four_pillar_v1_state.py` 在小节边界实施 Off/Fixed/Walk；关闭的组不能写音符，已锁定素材与组限制冲突时拒绝，不静默改写 |

`four_pillar_v1_model.py` 是正式的**未训练**联合网络入口；默认 3 层规划器、4 层事件解码器、宽度 192、6 头、32 小节历史和 2048 事件 token 上限。当前默认参数量 6,868,342，其中 1,581,309 是严格保留且冻结的旧四轨主干，5,287,033 可训练。缩小的是新增层数，**没有**缩窄宽度或减少注意力头：旧 H/M 的四层相容参数仍逐值移植 699,392 项，完整旧 R/H/B/M 主干仍可在可信过去窗口存在时提供四条独立先验。原 4/6 层配置仍可显式传参用于对照，但不再是默认值。另有 `four_pillar_trial_model.py` 和 `train_four_pillar_trial.py` 属于独立技术试训，不是本模型的训练入口；过去提供的 90 分钟命令不会训练这里的完整模型。

接口还包括四类任务（自由续写、给定旋律、给定和弦、给定动机）、结构化体裁意图、已知/未知材料掩码、速度 `log(QPM)` 条件及每四小节的保持/变化预测。谱面动态标记在精确事件 token 中；数值 dynamics 与 MIDI velocity 是不同的输出头，源缺失时不监督。`four_pillar_v1_objective.py` 为各项提供独立来源掩码及硬锁排除；权重只是待数值审计的占位值，不能直接作为正式训练参数。`four_pillar_v1_motifs.py` 只在小节提交之后更新过去动机库。

## 当前验证范围

- 旧检查点的每个参数严格加载；未来旧四轨字段即使被修改，只要在可见步数之后就不会影响输出。缺少可信旧格式窗口时先验为 `NO_PRIOR`。
- 动态声部编码能往返 70 声部、三/五/七等精确有理数，以及真实候选谱样例；不会在小节中间切断同时起音组。
- 教师强迫输入从事件流构建逐 token 的因果声部表；未来的声部身份 sidecar 不进入网络条件。声部指针在 `NOTE` 后预测，并在 `VOICE_CHOICE` 处反馈给后续组/角色/音高预测。
- 给定事件、组、角色和音区硬掩码；锁定声部/和弦；固定/游走组及速度边界；跨小节延音状态都有合成测试。
- 完整网络的前向和来源掩码损失可以反向传播，旧主干始终冻结。准备数据与无更新预检不会修改权重；此前独立小规模试训不等于此次全资料训练。
- `four_pillar_v1_alignment.py` 逐小节核对 OpenScore Lieder 原谱与同一固定提交的旧四轨网格；不匹配的谱例拒绝。`four_pillar_v1_pilot_data.py` 与 `train_four_pillar_v1_pilot.py` 已完成 8+2 对齐旧谱及 20+3 古典候选谱的双路径无更新预检，分别验证 `OLD_PRIOR` / `NO_PRIOR`。这个五分钟入口只覆盖自由续写的早期片段，不是正式十小时全语料训练。
- 本机 16 GB M2 Pro、当前项目环境 CPU 路径的无权重更新粗测：1024-token 完整前向约 0.07 秒、2048-token 约 0.18–0.19 秒；2048-token 单样本前向＋反向约 1.24 秒、进程峰值约 1.8 GB。这不是语法约束自由生成或正式训练吞吐量；当前 MPS 检测不可用。

本轮 `train_four_pillar_v1_all_data.py` 的语料清单与运行方式见 [README.md](README.md#四大件-v1全部现有真实语料训练专用2026-09-29-准备)。用户要求现有真实资料全部作为训练集、暂不设内部验证；该入口保存周期性状态但不选“最佳”权重。它首先训练自由续写；没有源可靠标签的任务/字段继续 mask，旧四轨网络仅在有严格对齐过去窗口时可用，不能在其他语料上伪造其输入。此轮只是扩大的研发训练，不意味着完整四任务目标已通过验收。

## 训练前仍须完成的工作

1. 全资料自由续写入口现在覆盖 45,240 份 SymphonyNet MIDI（原通过 43,036 + 精确时间恢复 2,204）、117 份当前精选 MIDI、1,131 首 Lieder 与 303 份古典谱；仍须扩展到四种条件任务和每字段的 source-known/lock 掩码。给定和弦标签只能来自可信来源。跨库剩余近重复、许可与**未来独立验证来源**仍须复核；不能把历史排除的重复 MIDI 或未批准的本地 MIDI 重新导入。
2. 实现语法约束的自由解码器与可追踪的 MusicXML/MIDI 导出；当前网络会给出 token/指针分布，但**不能宣称已经能独立生成可播放的完整新曲**。新 part/program/staff 的自由生成身份也需再细化。
3. 全资料入口只报告训练损失；独立验证、旧任务退化监测、同条件盲听和完整四任务训练仍待新素材与后续实现。损失权重尚未完成数值审计，不应把这次训练当成品质验证。网页端协议及音频时钟的整合另作独立验收。

用户已决定可先运行九小时训练专用实验；在完成上述验收前，不把检查点当作已验证正式模型，也不导出网页。
