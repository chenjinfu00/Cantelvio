# AIlegro 四大件模型 v1：实现规格与实验计划

**状态：架构设计定稿，四项能力的联合网络及事件/约束接口已实现并通过合成测试，但尚不能启动正式训练。** 本文规定下一代模型如何写和声、复调、曲式与配器；并规定精确节奏、力度、速度及用户素材如何进入同一流程。当前实现与缺口见 [FOUR-PILLAR-V1-IMPLEMENTATION.md](FOUR-PILLAR-V1-IMPLEMENTATION.md)。它不是当前网页的能力说明。当前网页和三个已部署权重保持不变。用户已决定：四项能力的完整数据、模型、损失、训练与短程技术验收都准备好之后，才启动新架构训练；不先训一个只有复调的候选模型。`scripts/train_four_pillar_trial.py` 可选用旧 H/M 部分参数作初值，仍不是本规格所要求的正式训练入口。

## 1. 目标、输入与不承诺的事项

目标输出是带小节、拍号、乐器/声部身份、实际音高、精确起音与时值、可用谱面表现标注的多声部事件流。至少允许 3/4、6/8、12/8、十六分音符，以及三/五/六/七连音；不以固定十六分网格截断其他比例。系统能连续续写，也能在未来接受用户给定旋律、动机或和弦后补写其余内容。

统一请求 `task / intent / material / constraints` 还必须带每项的 `time_span`、`known`、`hard_lock`、`source`。`task` 第一版实现自由续写、给定旋律补其他声部、给定和弦写声部、给定短动机续写；没有可信标签时，练习曲、夜曲等 `intent` 只保留结构化接口，不宣称模型已学会自由文本体裁。歌词和音节对齐不在 v1 内。未指定的乐器、角色、力度、速度都不是默认的监督真值。

四项最低可观察能力分别为：和声可在前文及给定材料下写和弦/低音与终止；复调至少有两个会相互回应但不只是加倍的有身份声部；曲式能跨 128 步窗口发展和回归动机；配器在**写音符时**受乐器资源、音区与角色控制，而非写完再分类。它们是评估目标，不是凭架构即可保证的质量。

## 2. 数据契约：一份作品、多个视图

唯一的底层时间单位是**有理数四分音符**。每首作品保留 `composition_key`、来源/许可、原始文件哈希、乐章、小节坐标、拍号、调号（已知才填）、乐器 `part` 元数据、`(part, staff, voice)` 身份、实际及可用的记谱音高、起音/时值、连音比例、谱面力度、渐强、重音、数值速度及各字段的已知掩码。谱面强弱、MusicXML 数值 dynamics、MIDI velocity 不合并为一种标签；QPM、速度文字和 MIDI tempo 也不合并。音高的缺失与打击乐无确定音高各有状态，不当作休止。

主视图采用按绝对起音排序的 `onset_slice`。一个切片含该时刻**所有**音符；切片内稳定排序只用于编码，听觉上同时发生。每个音符的完整时值可跨小节，解码器维护 `active_notes`，在以后的小节只延续、不重复发音；MIDI/谱面导出在小节线上产生必要延音。原始 MusicXML 的 tie 拼写未由目前事件视图完整保留，所以“不丢持续时间”不等于“逐字符还原原始谱面”。休止由某声部在区间内没有新音且没有 `active_note` 表示。装饰音用 `grace` 标志与零时值表示，不能静默转为普通音。

序列语法固定为：`SCORE_HEADER`（用户已知的调/拍与乐器表）→ `BAR_START`（小节长、拍号、已知条件的 mask）→ 若干 `ONSET`（首组从小节起点、此后从上一组起音算起的**非负增量**）→ 每组 `NOTE*` → `END_ONSET` → `END_BAR`。作品来源/许可保留在 manifest 中作审计，不凭空作为用户条件；原谱未来调号或速度变化若未由用户提供，也不能写进解码器条件。`NOTE` 先选已有声部指针或 `NEW_VOICE`，再输出 sounding pitch/无固定音高、实际时值、可用的 written pitch、连音比例、装饰音、力度字段。新声部登记其 part/staff/voice、乐器组、可用角色；同一身份之后不变。乐器组和角色是两个独立字段。已有乐器表是用户或乐谱**先验已知**的编制信息；不能把将来才出现的音符/声部当成已知。没有固定 32/64 声部上限：声部指针只对当前动态注册表做 masked softmax，必要时输出 `NEW_VOICE`；运行时可设置显式资源上限并报错，但不能丢声部。

`ONSET` 增量及 `NOTE` 时值用约分后的 `(numerator, denominator)`，通过无符号 LEB128 字节 token 编码，分母必须正、普通音时值必须正，装饰音可为零。相同有理数只有一种编码；训练可额外给常见分数 shortcut token，但必须解码到同一个精确值，罕见值走字节回退。连音比例是**记谱信息**，绝不再次乘进已经准确的实际时值。拍号只提供小节名义长度；弱起及异常小节用记录的实际长度，不强行补齐。每个切片结束时校验起音不越过该小节结束位置；跨小节 note end 合法。

只读统计已覆盖 `classical-score-v1` 的 303 首、3,010,494 个音符：单曲最多 41 个 part、62 个声部，同一起音最多 47 个音符；起音/时值分母最大见到 480（不是规格上限）。连音比例还出现了 `11:8` 等非目标比例。固定十六分或仅 3/5/6/7 的词表会有实测数据损失，因此使用精确分数回退。这个统计只是候选库的观测，不是训练划分或许可证明。

长曲训练按完整 `onset_slice` 切片，不能把一个同时起音组拆在两个样本；样本可从中间小节开始，但须提供前文的 active-note 状态、乐器/声部注册表与已完成小节摘要。训练采样的基本单位是作品，不是从同一曲切出的海量相邻窗口；防止长作品在损失中不成比例地重复计权。

## 3. 模型与因果信息流

```
已提交事件/小节摘要 ───────────────────────────────┐
用户已给定并标明可见范围的素材 ── KnownMaterialEncoder ┤
旧 R/H/B/M 权重 ── 条件可用时的和声草图/特征适配器 ─┤
                                                    ↓
     FormPlanner：最近 32 小节摘要 + 主题记忆 → 未来 4 小节计划
                                                    ↓
     EventDecoder：最近 2048 个事件 token + 计划 + 用户素材
                                                    ↓
      当前 onset_slice / 音符 / 声部 / 乐器角色 / 表现标记
                                                    ↓
      提交小节 → 更新摘要与动机记忆 → 规划下一段
```

**已训练旧主干**：从 `runs/joint-continued-expression-v1/best-base.pt` 严格加载旧 `StructuredJoint`，保留其 R→H→B→M 词表与权重作和声/旋律局部先验，不把它误称为新事件解码器。起始阶段冻结旧主干，只训练从其 hidden/logits 到新模型维度的适配器；后续可在保持旧任务验证不退化的前提下以小学习率解冻。旧主干的草图只由**已完成的过去**和用户明确锁定材料生成；不能由当前目标小节的真音符反推。新总谱没有可信 R/H/B/M 对齐时，输入 `NO_PRIOR` 而非伪造标签。网格草图是软提示，精确起音/时值以 EventDecoder 为准。`four-pillar-bootstrap-v0/init.pt` 仅为可迁移参数的来源/对照，其随机 GRU 与独立声部头不能直接冒充下述两层网络；迁移需在新检查点 manifest 里逐张量记录。现有 `--init-from-legacy` 技术试训仅把 H/M 的相容参数块移入新模型，不运行完整旧主干，也不构成这里要求的适配器。

**FormPlanner**：默认 3 层、宽度 192、6 头的因果 Transformer；输入最多最近 32 个已完成小节的摘要，以及一个从**过去事件**抽取的动机记忆库（初版最多 8 个代表片段，可随小节更新）。一次预测未来 4 小节的连续计划向量与受约束的可解释字段：相对密度、音区/织体、允许的组进入与退出、调性/和声方向（有可信标注才监督）、动机回归指针与移调/节奏变化。后一个 4 小节窗口可根据实际写出的内容重规划。未来目标小节可用来计算**损失标签**，不能在训练时作为解码器条件。段落 A/B、奏鸣曲式和“真正的终止”没有人工真值时，不强贴名称；动机匹配器产生的回归目标必须标 `proxy`，并有人审抽样。

**EventDecoder**：默认 4 层、宽度 192、6 头的因果 Transformer；本地窗口先定为最近 2048 个事件 token（按完整切片截断），跨注意力读取当前 4 小节计划、旧主干适配特征与已给定素材。四层恰好能保留旧 H/M 分支的四层逐值移植；旧 R/H/B/M 完整冻结主干的特征另以四个独立记忆向量进入解码器，仅在可信旧格式过去存在时使用。生成过程严格按时间与上述语法推进，已写的声部事件反馈到下一音符；一个 slice 直到 `END_ONSET` 才作为同时发声提交。字段头按语法状态分别预测新起音、声部选择、新 part/组/角色、音高、时值、谱面表现，不能让无意义字段参与当前状态损失。事件解码器跨小节保留 active-note 与声部表，不为每小节重置声部身份。原先的 4 层规划器/6 层解码器仍可显式配置为对照；默认缩减是资源取舍，不是已测得的音乐品质最优配置。

**KnownMaterialEncoder** 仅双向读取用户实际给出的事件；未知时间/字段先遮蔽。给定旋律/和弦等硬锁定素材在 EventDecoder 处作语法约束并逐事件原样输出，不靠“模型应该学会复制”保证。软提示可以影响分布但不锁定。若用户素材与拍号、乐器可奏音域等硬约束冲突，先返回冲突，不静默改音。训练时从真谱构造遮蔽/锁定任务，条件只包含所抽取的**已提供子集**；不能把未遮蔽的目标注入 encoder 或 planner。

**配器与角色**：模型在新声部建立及逐音事件时读取组 On/Off、固定/游走、用户指定角色/音域、当前演奏者可用性。Off 组在 part/voice 及音符处硬 mask；固定组在规划的小节里保持参与（允许明确休止/跨小节延音），游走组只在许可的小节边界换入/退出。用户固定角色优先，未指定角色为可学条件；不会把目前六组“写完再分配”的分类器当成真正的生成。对不明 group/role 的谱例，对应监督 loss 为零，音高与节奏 loss 仍可用。乐器范围 mask 以实际 sounding pitch 为准，允许用户显式选择扩展音域时解除默认限制。

**表现与速度**：精准时间与连音在事件层建模；谱面力度、重音、渐强、数值 dynamics 与 MIDI velocity 各有独立 source-tag 和 mask。数值速度作为当前 `log(QPM)` 条件输入；在可用的显式速度位置学习保持/改变及连续 `delta log(QPM)` 的条件分布，而非唯一正确 BPM 类别。固定速度严格服从用户 BPM；游走可在未排程的小节边界提出受用户范围/最大变幅约束的建议，可靠乐句边界出现时优先放在那里。速度文字不被伪转换成数值。声音层按排程前锁定的 tempo map 播放，不改已排程音符。

## 4. 训练样本、目标与优化

四种任务混合，同一份事件模型共享参数：①无给定材料的因果续写；②部分声部/整段旋律已锁定时补声部；③已知和弦时补旋律与伴奏；④已知短动机时发展/回归。针对④只把“作品内部可复验的片段相似与变化”当代理目标，不当人工曲式判定。每个 batch 样本带可见范围、硬锁范围与任务 ID；缺失条件由 mask 表示，不得自动填“C 大调/4/4/120 BPM”。给定素材的未来可见性与模型自身的未来目标严格区分。

损失按**可监督字段**分解：事件语法及起音/声部/音高/时值的条件负对数似然；已有可信和弦标签处的和声目标；动机回归指针/变形及下一小节密度/音区等可从未来目标计算的 planner 目标；有来源 group/role 的配器目标；分别有标注的力度与数值速度目标。每项先按已知样本数归一再加权，并逐源报告覆盖率；对未知标签 loss=0。对代理曲式目标单独标注验证表，不与人工评估混淆。教师强迫训练 EventDecoder 时只用**从过去预测出的计划**（可加 stop-gradient 或自生成计划）；不能输入未来小节的真值描述。固定初始权重、种子、词表/分割版本、逐源 loss 权重、优化器和采样策略记录在 manifest，损失权重在训练前通过小批次数值审计确定，不在此捏造最佳值。

数据源各司其职：`lieder-joint` 及其有效 expression/tempo 对齐主要提供旧四轨和声/速度监督；`classical-score-v1` 候选谱提供复调、精确节奏、乐器组及可用角色/表现目标；审核后的 `MIDI-Library` 仅在版权/内容筛选、作品去重、事件提取完成后参与；SymphonyNet 大库同样先解决来源、授权、跨库重叠与标签可靠性，不能因为它大就自动并入。尤其不能从历史 145 份本地副本或用户排除的“博士二阶段”目录重新导入。没有力度信息的 MIDI 仍可贡献音高、节奏等已知目标。

作品级近重复聚类在划分之前完成：同作品不同乐章需按实际复用风险决定同组；不同配器、移调、速度和轻微改写版本必须同一 split。跨库做元数据 + 音程/节奏指纹/局部匹配，人工复核边界样本。若与旧 SymphonyNet 测试作品相同，尤其 Beethoven 第六交响曲，从新训练和选模验证中隔离；测试集不参与阈值选择。先记录来源/许可与明确排除表，再确定 train/validation/test；所有窗口继承作品 split。不能用 Lieder 旧分割直接给新增谱库赋 split。

训练以**完整四大件路径**为唯一候选：先跑无更新的编码/因果检查，再做同一完整网络的一小批前后向及保存/恢复验收，合格才进入长期训练。可以在一个完整候选内部先冻结旧主干、后小学习率解冻，但每个阶段都保留 planner、event decoder、配器条件与四任务路径。旧模型、无 planner、无多声部、无乐器条件作为评估时的消融对照，而不是先单独训练并上线的中间产品。首轮真实模型应从版本化检查点续训；`training/runs/` 新目录不可覆盖已部署权重。

## 5. 推理、网页与导出契约

连续播放只在后台提前准备未排程片段，FormPlanner 每 4 小节展望，EventDecoder 按小节/切片生成；渲染和音频 onset 回调绝不临时运行网络。当前可听状态取 audio clock，不用领先的 scheduling counter。编辑未来和弦或开关/角色/速度时，只使受影响的**未排程后缀**失效，重新规划与生成；已排程事件不变。Stop/Panic 取消旧的生成结果、声音和回调；重启从最后实际听到的和弦及已完成事件摘要继续。

第一版模型可以先在 Python 离线生成 MusicXML/MIDI/WAV 供同条件盲听，**不自动接入网页**。网页需要新的事件协议、预测和播放一致性、精确拍号/连音排程、tempo map、PyTorch/浏览器输出对照，以及对当前八小节和弦谱的时间映射；旧权重与词表不能被新模型文件直接覆盖。导出新运行时要另立版本、更新来源清单/许可说明，并经用户试听选择是否替换主页。

| 作品级评估 | 预先冻结 held-out 曲目、指标及盲听样例；报告每项任务的条件遵守率、精确时间、声部独立/加倍、动机回归、音域、速度/力度覆盖和旧和声能力变化 | 尚无新模型结果 |
| 运行安全 | 新版本检查点、词表、数据 split、优化器/RNG/游走状态/训练日志可恢复；绝不覆盖主页权重 | 技术试训写独立 `training/runs/` 并保存优化器/RNG、数据哈希；网页导出禁用。正式模型恢复与游走状态仍未完成 |

任何一项关键门槛未过，不给“整夜正式训练已准备好”的结论。技术短测不等于音乐质量保证；新模型若不优于当前版本的盲听与可控性，继续保留旧网页版。

## 7. 实现顺序、实验记录与参考

1. 冻结数据/许可/去重/split 清单；补齐精确事件编码器、解码器及针对上述边界的单测。若某类谱例不支持，必须在 manifest 里明确排除，不能悄悄量化或删音。
2. 实现 FormPlanner、动机记忆、EventDecoder、active-note/声部表、给定素材锁定与跨源 loss；完成旧权重张量迁移审计。先做“改变未知未来不影响过去”的自动测试。
3. 实现只跑完整四大件路径的训练/验证入口，记录 source 与 mask 覆盖、损失分项、参数/显存或内存需求、完整 checkpoint；短测通过后才议定设备、训练时长与正式启动命令。
4. 在固定 held-out 输入上和当前网页基线/消融模型对照，做盲听；仅在稳定且用户同意时开启新模型网页接入。

本规格的实验问题是：在同一可审数据与盲听条件下，分层计划＋真正多声部事件解码＋生成前配器，是否比现有局部四轨模型更好地满足长期结构、声部独立和乐器约束，而不损失和声与播放可靠性。主要证据是**预注册的条件遵守率和同条件盲听**，验证 NLL 仅是辅证。尚未设定任意“达到 X% 就好听”的成功阈值；阈值应在固定测试样本与评价流程确认后、查看新模型结果前确定。隔离技术试训命令见 `training/README.md`；目前不存在安全的一行**正式**四大件训练命令。

相关研究是方法参考而非本项目已复现的结果：[Museformer 的细/粗粒度长程注意力](https://proceedings.neurips.cc/paper_files/paper/2022/hash/092c2d45005ea2db40fc24c470663416-Abstract-Conference.html)、[MIDI-GPT 的多轨条件补写](https://ojs.aaai.org/index.php/AAAI/article/view/32138)、[FIGARO 的可解释描述条件](https://openreview.net/forum?id=NyR8OZFHw6i)。具体两层规模、精确有理数编码、旧模型适配与验收规则是 **AIlegro 的设计选择**，仍需实现和消融验证。
