## 512 小节窗口

训练取样、摘要张量、规划器位置嵌入、动机候选搜索及离线生成端均使用配置中的历史长度。当前默认 `--history-bars 512`，可显式选择 1–512；生成端从检查点配置读取，兼容旧 32 小节结构的离线加载。短乐曲只使用实际已有的小节，其余位置被掩码；每步日志的 `historyBars` 与 `knownHistoryBars` 分别记录容量和实际历史数。

与上一修订的 32 小节模型相比，只增加 `(512−32)×192 = 92,160` 个位置嵌入参数。层数、宽度、事件词表、2048-token 精细事件上下文、4 小节规划跨度和最多 8 个动机槽位均保持原配置。这是 512 小节的 20 维摘要记忆，不是完整保存 512 小节的全部音符。动机仍选最近最多 8 个合格片段，只扩大候选搜索范围。

新启动目录为 `runs/four-pillar-v2-history512-20260930/`。32 小节模型的位置表形状不同，不能用当前默认参数直接 `--resume` 或 `--init-checkpoint`；任何旧模型迁移必须明确实施。精确恢复还要求代码哈希一致；本次改动后的脚本不能直接精确恢复改动前的运行。

## 本次已补齐的训练路径

1. **密集小节与真实上下文。** 每个目标小节按完整同时起音组切成可采样片段，后半段及 END_BAR 都能进入训练，前面的片段仅作上下文、不重复算损失。窗口包含实际先前音符；跨小节长音及仍在持续的音通过因果状态输入保留。休止小节也参加抽样。单个起音组超出显式资源上限时记录拒绝原因，不悄悄删掉同一和弦中的声部。
2. **和声监督及旧主干。** 使用来源一致且逐小节精确时间对齐的 Lieder/AugmentedNet 和弦分析，移调时同步移动和弦根音；和弦分析是有来源的代理标签，不是人工真值。严格对齐的过去窗口可使用冻结旧四轨分支。无法对齐的乐曲仍参加可支持的任务，但不伪造和弦或旧先验。
3. **四类任务。** 按来源支持情况混合自由续写、给定高声部补写、给定和弦补写、给定过去动机续写。高声部是明确的选取代理，不冒称人工旋律标注。提供的音符只以选中的子集进入条件，锁定音符及锁定和弦不作为复制损失。未来未知内容不进入条件。给定材料同时进入小节规划与局部事件生成。
4. **力度与速度。** 接入原有 MusicXML 数值力度和显式数值 QPM；MusicXML 力度百分比除以 100，与 MIDI velocity/127 使用不同输出头。按 part 与精确时间继承原标记；同位置冲突值保持未知，直到下一条明确标记。两首需要原谱时间修复、与旧数值标注尚不完全一致的 Lieder 暂时不使用数值 sidecar。MIDI 直接核对原始 FF51 速度事件，不把隐式 120 BPM 当真值。无来源大小调信息时，不强填 major。
5. **动机与配器规划。** 动机经过带位置信息的编码器，保留顺序；同时监督有证据的动机回归、移调和时值比例。增加有直接音符依据的音区、密度与组活动目标；未知组不被误当作“该组不活动”。大曲式、织体和体裁没有可靠标签时仍不假造监督。
6. **数值稳定。** 新连续输出头采用稳定初始均值/方差，并限制预测方差范围，避免随机极小方差造成的力度损失主导。学习率有 100 步预热及梯度裁剪；每一步持久记录各项损失、标签数、任务、片段位置和拒绝原因。损失权重是可审计的研发默认值，并未证明为音乐质量最优。
7. **完整恢复。** 原子写入并同步检查点，保存模型、优化器、两类随机状态、来源遍历位置、累计计时及累计任务统计。同一目录使用系统文件锁防止双写。Ctrl-C/SIGTERM 在完整步骤边界停止并保存；异常中止保留上一个完整周期检查点。预检与初始化耗时不计入训练预算。
8. **数据内容核验。** 已为全部 45,357 份 MIDI 冻结 SHA-256 内容指纹，成员资格不变。启动时全量核验，抽样时再核对对应文件；即使文件名没变，内容变化也会拒绝训练。哈希清单、乐谱索引、表现标注、和弦资料、代码和配置都进入运行 manifest。

过去版本“只训练小节开头、显式和弦头无监督、数值谱面力度未接入”的说明现在属于历史状态。旧的 `runs/four-pillar-v1-all-data-20260930/state.pt` 已按此前要求删除，不应恢复。

训练成员仍是 **45,357 份 MIDI + 1,434 份乐谱记录**：45,240 份 SymphonyNet、117 份当前精选 MIDI、1,131 首 Lieder、303 份古典谱。它们是来源记录数，不保证跨库作品唯一。继续排除程序生成的 10,112 个乐句、历史 145 份本地副本及用户排除目录。没有下载新语料，也没有改变用户选择的“全部现有资料训练、另找新资料评估”方案。

整体移调保持精确时间、力度和声部关系，按安全音域选择移调量；它是数据增强/过去参考归一化，不等于神经网络严格等变。复调表示已支持身份声部与重叠长音；是否会写有质量的独立声部，要由训练后新资料上的生成评估判断。细粒度 rubato、踏板及大型曲式并未因这次工程修订而自动解决。

## 检查、训练与恢复

从 AIlegro 项目根目录执行，仅检查：

```sh
bash training/run_four_pillar_v2.sh --preflight
```

同一脚本去掉 `--preflight` 即开始累计十一小时；512 小节摘要历史、2048-token 事件窗口，每五分钟保存，macOS 防空闲休眠。默认输出 `training/runs/four-pillar-v2-history512-20260930/`，新训练必须使用新目录。可用 `--history-bars`、`--max-seconds`、`--output-dir`、`--lr`、`--warmup-steps` 显式覆盖配置。

```sh
bash training/run_four_pillar_v2.sh
# 意外中断：同一配置恢复累计剩余时间
bash training/run_four_pillar_v2.sh --resume
```

恢复必须匹配数据内容、代码、配置与 manifest。强制杀进程或断电只能恢复最近保存点；完成预算后 `--resume` 不会自动追加时长。

**训练后仍可继续改进。** 相同结构（包括历史窗口长度）可从一个已停止且不再改写的修订 2 检查点另开训练，旧文件保持原样：

```sh
bash training/run_four_pillar_v2.sh   --init-checkpoint training/runs/OLD_RUN/state.pt   --output-dir training/runs/NEW_RUN --max-seconds 3600
```

这里严格加载兼容模型权重，重置优化器、随机抽样和计时，并记录父检查点哈希与步数。继续这个新运行时，要保留相同的 `--init-checkpoint` 等参数并加 `--resume`。结构/词表不兼容时明确报错，需另做权重迁移；不会默默丢掉不匹配参数。这样区分了“精确恢复”和“从旧权重开始新实验”，而不是把训练视为以后再也不能改动。

## 离线自由生成与导出

`sample_four_pillar_v2.py` 从完成的提示小节开始，以自回归方式决定新起音、时值、声部和音高，不复制未来真谱或上一小节节奏骨架。训练完成后可运行：

```sh
.venv-training/bin/python -B training/scripts/sample_four_pillar_v2.py   --checkpoint training/runs/four-pillar-v2-history512-20260930/state.pt   --score-id lc6212179 --prompt-bars 4 --bars 4   --seed 1 --qpm 90 --output-dir training/runs/four-pillar-v2-sample-1
```

输出 `score.json`、`score.musicxml`、`preview.mid`，不写网页权重。提示来自训练库，仅供诊断，不作独立评估。默认固定速度，可用 `--tempo-mode walk` 采用有范围限制的小节速度建议。Python 生成接口还支持已给定声部的原样保留、和弦/动机条件及显式声部/音符资源上限。

推理使用声明的有理数分母集合、有限音域和资源上限；达到音符上限时的强制收束会记入审计，并非训练数据量化。JSON 保留精确事件，MusicXML 用延音线保存跨小节持续时间，必要时补尾部小节；谱面采用实际发声音高，不承诺原始异名同音拼写。MIDI 超过格式分辨率时会在审计中报告试听量化误差；缺少 MIDI 鼓身份的无固定音高事件保留在 JSON/谱面，并明确列出在 MIDI 中未映射的项，不悄悄指定鼓音。当前没有自动网页导出，浏览器推理/排程整合应另行验收。
