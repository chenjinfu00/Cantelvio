## 产品目标

用户输入一段旋律，选择钢琴或六组乐器、密度、音区和风格，得到可编辑的伴奏。
输入旋律的音高、起音和时值保持原样；用户修改和弦或后续材料后，只重新生成受影响且尚未提交的部分。
当前固定时间词表不一定表达任意输入分数时值。预检必须核对映射：无法精确表达时明确提示或保留原输入轨旁路，
模型条件转换的近似误差单独报告，不能在返回或播放时静默改写原旋律。
第一阶段优先 8–16 小节的钢琴伴奏，覆盖休止、跨小节延音、弱起和复合拍；效果稳定后再扩大到室内乐与六组配器。

界面以给定旋律和六组乐器为主要操作对象。低音、和声、内部声部身份仍可作为模型内部结构，
不要求用户重复管理三套角色栏。允许某组演奏与要求该组必须发声应是两个明确不同的控制含义。

## 当前可依据的事实

| 事实 | 依据及边界 |
| --- | --- |
| v3.1 是规划器加事件生成器，音符属性由轻量解码器顺序决定 | `training/scripts/four_pillar_v31_model.py`。每个完整事件运行一次主干；不能再把当前模型当成每项属性都重复运行大 Transformer 的旧方案 |
| 给定旋律尚无专用条件通道 | 原模型按事件顺序读已发生内容，同一起音先和弦后音符；当前锁定音机制保证保留输入，但不足以让所有较早的和声决策预先看到整段旋律 |
| 已有配和声小模型和任务解码层 | Score 适配器可先读旋律给和弦，再锁定旋律和和弦生成伴奏；应作为可运行基线保留 |
| 多候选已有冲突惩罚接口 | `TaskComposer.best_of(..., clash_penalty=0.)`。默认仍只按锁定材料概率排序；检查到 Score 适配器调用时未传惩罚。近期工作是接通、调参与对照，不能宣称该接口已改变默认表现 |
| 和弦评估混用标签的问题已被识别 | `four-pillar-v31-parts-labelled-20261004.json` 按训练标签重算：历史第 101,129 步根音和性质损失均优于第 45,225 步。先前“和声变差源于权重噪声”不能作为结论 |
| 训练集损失不能证明泛化或音乐质量 | 现有主模型材料全部用于训练。配和声模型的留出作品也可能已进入主模型训练，不能把它们直接当作整个系统的独立测试集 |
| 连续演奏与 Score 当前使用不同模型路径 | 连续演奏服务仍调用 v2 performance 脚本，Score 作曲任务是 v3.1。改善 Score 配伴奏不等于已经改善主页连续生成 |

v3.1 标准配置现场实例化计数为 **5,014,967 参数**，FP32 参数本身 **20,059,868 字节，约 20.06 MB**。
本地 `four-pillar-v31-ready-20261001/weights.pt` 文件约 20.14 MB；优化器、训练状态和推理缓存另占空间。
这不是主页 v2 的参数计数。新模型规模只有实现后才能精确报告。

## 阶段安排

| 优先级 | 工作 | 交付物 | 进入下一步的条件 |
| --- | --- | --- | --- |
| P0 | 固定模型版本、输入与独立测试素材，检查音符链路 | 带哈希的 benchmark manifest、测试材料清单、基线报告、MIDI 和同音色试听 | 输入旋律保持 100%，模型至播放的音高映射检查通过；训练重叠和未知来源明确记录 |
| P1 | 接通现有冲突评分；比较不同候选数与配和声方式 | 少量候选的质量与延迟表，候选各项评分明细 | 不靠机械删除不协和音，不抄写整条旋律；在相同预算下优于当前默认，或明确说明未改善 |
| P2 | 跑官方 AMT 对照并评估直接引擎接入 | 同一旋律、同一长度的伴奏、转换误差与延迟报告 | 按效果、控制和资源预算决定开放 AMT 引擎、改进 v3.1 或保留当前基线 |
| P3 | 若对照显示需要，给 v3.1 增加旋律条件通道，分两步微调 | 独立候选权重、迁移清单、输入条件消融与无条件回归 | 新模型在未用于调参的材料上改善伴奏，同时不破坏锁定音、控制和速度 |
| P4 | 钢琴效果稳定后扩到室内乐、六组乐器及连续演奏 | 分编制评估、六组控制检查、长时间播放记录 | 乐器音区合理、声部连续、控制生效；实时续写满足播放预算 |
| P5 | 乐句结构、段落重复变化和更丰富表现 | 32–64 小节任务与分段试听 | 短段伴奏已有稳定收益，才扩大曲式目标和模型规模 |

P0、P1 最先落地。暂不承诺某天完成或固定训练小时数：AMT 本机兼容、数据标注时间和基准延迟尚未量测。

## 架构方案与选择依据

### 首选候选 A 旋律条件通道

保留现有事件主干、调性相对音高、精确时值词表、小节规划和参考机制，新增较小的旋律编码器。
它读取用户明确给定的旋律，包括音高、起音、时值、休止、跨小节延音、拍号及可用调性信息，
把当前乐句及邻近小节的材料提供给和弦与音符属性解码器。至少和弦、起音、音高和时值决策都应能读取这份条件。

旋律条件属于已知输入，生成的伴奏目标不应偷偷进入编码器。自由续写时不给未来材料；
若以后支持边演边伴奏，要单独规定“当时已知的旋律”，不能复用离线看完整旋律的指标来承诺实时能力。

先尝试把新条件接到属性解码器，维护原主干缓存的依赖关系；已固定的条件可预编码。
这是一项设计假设，可能限制条件影响力，因此要与更深层条件注入对照。若条件进入主干注意力，
需要明确记录缓存依赖，用户编辑条件后使相关缓存失效；不能只修改条件仍继续用受旧条件影响的缓存。

第一步冻结旧主干训练新分支；第二步以较低学习率有限解冻，并混入无条件续写任务防止原能力退化。
训练目标只要求模型补出缺失的伴奏，保留真实给定声部和明确目标声部；不能把最高音自动当成所有作品的真实旋律。

建议把第一版总规模预算控制在约 **600–800 万参数以内**，对应 FP32 参数约 **24–32 MB**。
这只是候选预算，不是已生成模型的大小，也不保证更快；保留 501 万参数基线作同机对照。

### 候选 B AMT 式提前插入控制事件

[AMT 论文](https://arxiv.org/abs/2306.08620)及[官方实现](https://github.com/jthickstun/anticipation)
通过把控制事件与生成事件交错组织，支持给定旋律等材料下的补全与伴奏。
本项目可以借鉴“在决策前让模型看到已知控制”的机制，保留自身精确记谱和调性表示。

这一方案会增加事件数量，且改变训练和解码序列。效果和延迟都要实测，不能把提前插入控制理解为天然更快。
若 A 在相同数据和预算下始终不足，而 B 的小实验有明确优势，再承担表示迁移的工作量。
官方 AMT 权重并不是本项目 v3.1 的可续训检查点，不能把两套参数或优化器直接拼接。

### 现有方案作为基线

现有“配和声模型读旋律，再让 v3.1 写伴奏”的方案已有代码和权重，是最便宜的起点。
即使新增条件通道，也保留用户给定或修改和弦的入口。和声分析标注、从旋律推荐和弦以及伴奏生成是不同任务，
不因为采用同一套和弦词表就混用标签或评价方法。

## 代码实验计划

**研究问题**：预先读到给定旋律，是否能在较少候选、相同运行预算下改善伴奏，而保持原旋律和六组控制？

**待检验假设**：与现有 v3.1 方案相比，旋律条件通道可在 K=1 或 K=4 时获得至少可比的伴奏质量，
减少为找到可用结果而重复生成的次数。假设尚未验证；如果不成立，应保留基线并记录失败。

### 对照组和控制变量

| 组 | 要比较的因素 |
| --- | --- |
| G0 | v3.1 直接锁旋律，单候选 |
| G1 | 当前配和声模型加 v3.1，K=1、4、8，现有评分 |
| G2 | 相同权重、相同 K，接通冲突评分并在开发集调权重 |
| G3 | 官方 AMT 旋律控制，明确无同构显式和弦输入的差异 |
| G4 | 候选 A，旋律条件开启与关闭、冻结阶段与微调阶段 |
| G5 | 仅在需要时尝试候选 B 的小规模对照 |

固定每组的旋律、起音、速度、生成长度、允许乐器、音区与采样预算。
初步每首使用同一组 5 个种子；不同架构无法保证随机采样路径相同，种子只帮助复现，不能声称逐次随机数等价。
报告同候选数与同时间预算两种比较。所有试听用同一音色渲染并匹配响度，以减少音色和音量对判断的影响。

AMT 的秒时间与本项目记谱时间需明确转换。原锁定旋律不被量化替换；AMT 原始控制与输出的转换误差另外报告，
不能以事后回贴原旋律掩盖控制漂移。无法公平表达的条件列为不可比，不用强行包装成完全相同的任务。

### 评价与建议验收门槛

| 方面 | 指标与检查 | 建议门槛或解释 |
| --- | --- | --- |
| 输入保持 | 音高、精确起音、时值、跨小节延音逐事件对比 | 100%；不能以只保留音符数量代替 |
| 播放一致 | 模型实际 MIDI 音高 → Score 实际音高 → 播放与导出事件；打击乐另核验 GM 键 | 映射完全一致；移调记谱与实际发声音高分别核对 |
| 伴奏可用性 | 隐去版本后试听，记录是否愿意直接保留、修改负担、声部连贯与收束 | 作为主要质量证据；用户个人试听不是正式人口研究，不能虚构人数或显著性 |
| 和声诊断 | 持续不协和、强拍音、和弦过密、与旋律的同音重复 | 辅助指标；半音冲突不是一律错误，不能追求零冲突或强制每音都在和弦内 |
| 旋律独立性 | 伴奏是否原样抄写整条旋律、是否长期只有同度或八度叠置 | 区分有意加倍和机械复制，并统计出现比例 |
| 配器与控制 | 关闭组发声、超音区、重复音、声部跳跃、休止与延音结构 | 关闭组发声为 0；结构非法事件为 0；音区与音乐性另评 |
| 速度与资源 | 首次加载、旋律编码、首段完成、每小节或每事件时间，P50/P95、峰值内存 | 测实际 Mac，不拿历史云端秒数替代；分别报告密集与稀疏小节 |
| 连续演奏 | 续写速度 / 可播放时长，断流、重启、编辑后旧音取消 | 后续实时目标：暖态 P95 生成时间不超过片段播放时长的 0.5，代表两倍预留；这是建议目标，尚未达到验证 |

配对比较以作品为单位汇总，每首保留各随机种子的波动，不把音符数或种子数当作独立作品样本数。
先看实际效果和修改负担，再报告不确定性；不只拿平均损失或单一 p 值决定升级。
条件评分权重仅在开发材料上确定，封存测试只在候选冻结后查看；如果根据测试结果继续调参，应将其改标为开发集并另找测试集。

训练监测记录进程状态、已保存步数、损失、用时及检查点；崩溃或明显异常先记录，不自行反复重启新训练。

## 数据与加速工作如何服务主目标

先核查并完成 AugmentedNet 标注侧文件和训练加载路径。当前已见新标签侧文件加载代码，但本地数据目录未见相应
`chords-augmentednet-v1.json.gz`；不能把接口已写好当作重标已完成。统一标签时保留来源、版本与置信度，不能把自动标签当作唯一正确和声。

PDMX 先取适量、适合旋律配伴奏且质量可检查的材料，再扩大规模；77,321 条候选索引不会直接等于 77,321 首训练谱。
MuScriptor 的真实录音评估作为独立支线，避免把转写错音混入生成模型的“正确伴奏”监督；补音结果标明推断来源。

加速先量测各阶段，优先条件编码复用、保持主干 KV 缓存有效、降低候选数、限定生成长度和音符密度。
再考虑 ONNX、精度或量化方案。[ONNX Runtime 文档](https://onnxruntime.ai/docs/performance/model-optimizations/quantization.html)
提供量化路径，但本机是否更快、生成分布是否改变都需要核验。加速失败时保留原路径。
用户允许的合法音符不能为追求速度被静默删掉；限密度、限长度应成为明确控制。

## 旧模型如何继续使用

| 变化 | 可继承什么 | 训练状态如何处理 |
| --- | --- | --- |
| 只改候选评分或服务调度 | 原权重全部保留 | 不需要重训 |
| 同架构继续训练 | 原模型权重和匹配的状态 | 配置、词表、数据与状态均匹配才是精确 resume |
| 学习率衰减和 EMA 新运行 | 可从现有 v3.1 权重初始化 | 现有 anneal 脚本明确重置优化器，属于新运行；生成质量改善仍需比较 |
| 新增旋律条件通道 | 名称与形状兼容的旧参数 | 新参数另训、保存迁移清单；不直接复用旧优化器或伪称无损续训 |
| 改为 AMT 事件组织 | 部分兼容参数是否可移植需逐层核验 | 词表和序列语义改变，要新运行；官方 AMT 作为独立模型对照 |

所以可以继续利用已经训练的模型，但“沿用已有权重微调”与“按原状态精确续训”是两件事。
现有 Score ADR 0008、0009 继续描述已实现路径；本方案不自动推翻它们。
若候选 A 或 B 验证后被采用，再为新版本写 ADR，决定接口与版本迁移，才进入网页切换。
