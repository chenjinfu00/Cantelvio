# AIlegro 管弦乐模型：设计（2026-09-28）

## 目标与已定的决策（用户，2026-09-28）

- **通用架构**：用通用 Transformer，不再做四轨各自的子网络。joint-v1 的对照实验表明，参数足够时通用模型一样好，见 `../runs/joint-v1/REPORT.md`。
- **规模**：做得更大，能写整首交响乐式的多乐器音乐。离线用大模型写整首，网页里用小一些的版本实时演奏。
- **乐器分 6 组**：木管、铜管、打击乐、竖琴/键盘、高音弦乐、低音弦乐。每小节由模型决定哪些组演奏；用户锁定的组直接固定。
- **12 平均律的平移对称性**：
  - 模型不区分调，参数在所有调之间共享；
  - 训练时把曲子随机移调。
- **数据**：研究用 MIDI 大数据集，先用 SymphonyNet。其中单个文件版权不明，模型只用于研究和个人使用。
- **训练机器**：用户的 M2 Mac（PyTorch MPS），用 `mac.sh` 启动。

## 数据（`prepare.py`）

- **来源**：SymphonyNet 交响乐 MIDI 数据集，46,359 个文件、约 3,284 小时、2.79 亿个音符（symphonynet.github.io，Google Drive 下载）。数据集没有写明授权。
- **乐器分组**：每个 General MIDI 音色对应一个组，见 `groups.py`。
  - 弦乐合奏、震音/拨奏弦乐、合成弦乐与铺底、合唱这几类覆盖整个音域的音色，以 G3 为界分到高音或低音弦乐。
  - 鼓通道的音符是**无音高打击乐**，保存鼓的种类，移调时不动。
  - 合成效果和音效丢弃。
- **量化**：起音与时值量化到 1/12 个四分音符，能精确表示十六分音符、八分三连音和十六分三连音。
  - 小节由拍号生成，拍号在小节中间改变时，该小节截短。
  - 起音不在网格上的比例超过 20% 的文件（演奏录制的 MIDI）跳过。
- **合并齐奏**：同一组在同一时刻奏同一个音（例如第一、第二小提琴齐奏）只保留一个，取最长的时值和最大的力度。
- **划分**：按内容哈希分为训练 98%、验证 1%、测试 1%，完全相同的文件去重。
- **存储**：每个字段一个原始数组文件，训练时用 memmap 读取，不需要把数据全部读进内存。

## 表示（`data.py`）

每个小节依次是：

- **BAR token**：
  - 拍号（15 种常见拍号 + 其他）；
  - 速度（30–300 BPM，按对数分 32 档）；
  - 这一小节在全曲中的位置（16 档）；
  - 6 个组各自是否在这一小节出音。
- **每个音符一个 NOTE token**：
  - 小节内位置（0–127，单位 1/12 四分音符）；
  - 组；
  - 音高字段；
  - 时值（32 档，最长 32 个四分音符）；
  - 力度（8 档）。

**顺序**：同一时刻的音符，无音高打击乐在前，有音高的从低到高。曲子结束处有 EOS。

**音高是相对的。**

- **音高坐标 π**：每个 token 都有一个。有音高的音符取自己的音高；其他 token 取在它之前最近一个有音高音符的音高。窗口开头第一个有音高的音之前，π 取锚点 C4。
- **音高字段**：有音高的音符记与前一个 token 音高坐标的**音程**（−60…+60 半音）。无音高打击乐记鼓的种类。
- 因此模型输入里的音高信息只有音程，以及可选的粗音区。

**移调增强**：同一窗口里所有有音高的音一起平移 −6…+5 个半音，并保持在钢琴音域 A0–C8 之内。音程字段不变，改变的只是 π。

## 模型（`model.py`）

通用解码器 Transformer：pre-LN，GELU 前馈，因果注意力，同一套权重。

**时间旋转编码**：每个头的前 16 维按起音时间 t（以四分音符计）旋转，周期为 1/2、1、2、4、8、16、64、256 个四分音符。注意力因此只依赖时间差，同时发声的音时间差为 0。

**音高旋转编码（12 平均律对称性）**：

- **旋转**：每个头另取 18 维，组成 9 对，按 θ = ω·π 旋转。
  - ω_k = 2πk/12（k = 1…6），是音级圆上的 6 个谐波，决定"相差几个半音（模八度）"；
  - 另有 2π/24、2π/48、2π/96 三个慢频率，用来区分相差一个或几个八度。
- **查询与键**：同一对向量旋转后的内积只取决于 π_j − π_i，所以注意力分数只依赖音程。
- **值**：同样按键的音高旋转，输出再按查询的音高转回（值旋转）。头读出的内容也只含相对音高：Σ_j a_ij R(ω(π_j − π_i)) v_j。
- **音高输出头**：预测相对前一个坐标的音程，而不是绝对音高。
- **结论**：去掉音区输入后，整个网络对整体移调**严格等变**，所有调共用同一套参数。`tests/test_model.py` 检查了这一点：所有 π 平移 −7、1、5、12 个半音，logits 最大变化 2×10⁻⁷，仅为浮点误差。
- **音区输入**：可选（register），按半八度分 16 档，给出粗的绝对音区。乐器音域和音色确实取决于绝对音高，所以这是有意为之的轻微破缺。

**输出**：位置 i 预测 i+1 个 token，逐字段预测，每个字段都以已选出的字段为条件。

- 先预测类型；
- BAR：拍号 → 速度 → 6 个组位依次。这样用户锁定的组能影响其余组的选择。
- NOTE：位置 → 组 → 音高 → 时值 → 力度。

**损失**：每个 token 所有字段的负对数似然之和，按 token 平均。

**测试**：
- `tests/test_pipeline.py`：窗口与存储数组逐音对照，含移调、截断、EOS 和组位。
- `tests/test_model.py`：
  - 因果性：跨 token 和同一 token 内的字段顺序；
  - 严格等变；
  - 数据侧移调后损失不变；
  - 能过拟合一个 batch。

## 对称性实验（`mac.sh ablation`）

同一数据、同一小模型（d=256、4 层、上下文 1,024 个 token）、同样 6,000 步，比较五种设置：

| 配置 | 音高 | 移调增强 |
|---|---|---|
| `abl-absolute` | 绝对音高嵌入与输出（普通做法） | 无 |
| `abl-absolute-aug` | 绝对 | 有 |
| `abl-rotary` | 音高旋转编码 + 音区 | 无 |
| `abl-rotary-aug` | 音高旋转编码 + 音区 | 有 |
| `abl-rotary-exact-aug` | 音高旋转编码，无音区（严格等变） | 有 |

- **评估集**：固定的验证窗口，原调和整体移调 +5、−4 三种。
- **判断**：
  - 对称性有没有帮助，看在原调上验证损失的高低，以及学得多快；
  - 模型是否只学会了训练数据里常见的调，看移调后的损失变化多少。

## 生成（`sample.py`）

- **乐器组控制**：每个组设为 `on`（必须演奏）、`off`（静音）或 `auto`（模型逐小节决定）；可以用计划文件按段落改变设置。
- **采样规则**：
  - "发生什么"用模型原本的分布：换小节、音符位置、哪个组。这是 joint-v1 盲听得出的经验，截断会让音乐停滞。
  - 温度和 top-p 只作用于音高、时值和力度。
- **长度与结构**：生成长于上下文时，从小节线处重新开窗。BAR 的"全曲位置"字段让模型知道自己在开头还是快结束。
- **输出 MIDI**：每组按音区选演奏音色。

## 限制与下一步

- **长程结构**：上下文最多 2,048 个 token，大约 10–40 小节，取决于织体密度。主题再现、乐章级的曲式超出这个范围，需要以后加更长程的记忆或段落条件。
- **数据**：SymphonyNet 的质量和来源不一，其中编配与乐器的对应也取决于制作者。
- **网页版**：先由对照实验选定结构，再训练 `web` 配置，然后写浏览器推理和管弦乐音色。VSCO 2 社区版采样是 CC0 授权。
