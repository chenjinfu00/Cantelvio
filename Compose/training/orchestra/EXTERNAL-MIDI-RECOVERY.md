# 外部 MIDI 整理核查（2026-09-28）

范围：这台电脑 iCloud Drive 中 AIlegro 项目以外可读取的 257 个 `.mid` / `.midi` 文件；不包括 Julia 包的测试 MIDI，也不包括 AIlegro 自带的 SymphonyNet 大语料。只读解析；没有更改、复制原始 MIDI，没有开始训练或替换网页权重。

| 结果 | 文件数 |
| --- | ---: |
| 原筛选通过 | 187 |
| 原筛选不通过 | 70（离格 60、音符太少 6、拍号不可表示 4） |
| 开启保守恢复后新增通过 | 45（离格 44、音符太少 1） |
| 恢复后仍不通过 | 25（离格 19、拍号不可表示 5、短于 8 小节 1） |

恢复后共有 232 个通过的文件；按当前解析器的精确内容指纹去重后为 211 个。新增的 45 个文件对应 36 个此前没有的内容指纹，合计约 145,335 个去重后音符。内容指纹只能去除高度相同的版本，不能证明这些是 36 首独立作品；同曲改编、转调、导出版本仍可能重复。

`prepare.py --recover` 是选择性转换，不改原文件：最低保留音符数由 100 降为 60；超过原离格比例的 MIDI，只有在按每个音符处的速度换算后，起音落到 1/12 四分音符网格的平均误差 ≤15 ms 且 95% 分位误差 ≤35 ms 才接受。转换信息留在 `pieces.json` / `prepare.json`。默认运行不用该模式，原有五组模型不受影响。

**限制与下一步**

- 剩余 19 个离格文件若强行吸收，可能破坏原来的演奏节奏。另有 5 个拍号无法直接放入当前网格／小节长度（例如 11/4、12/4、某些 32 分音符分母的特殊拍号），以及 1 个实际不足 8 小节的片段。它们仍保留为候选，不伪造小节或填充音符。
- 此恢复只衡量起音网格偏移；持续时值还会由现有编码量化并映射到离散时值表。五连音等不在 12 格网格上的细节可能丢失。要学习这类表现力，应使用更高分辨率或事件时间编码，并做独立验证。
- `data.py::Corpus.window` 已在训练时从作品随机小节开始取最多 `max_len` token 的动态片段，因此不用再把整首 MIDI 复制成许多小文件。该实现可能在长度上限截断末尾小节；完整乐句采样是后续独立改进项。
- 目前 `prepare.py` 默认按内容哈希划分训练／验证／测试。如果先拆成多个实体片段，或纳入同一作品的多个改编版本，就会有跨集合泄漏风险。真正合并新语料前，必须先核对作品身份与授权，按作品划分，再做片段采样；还需抽样试听／检查乐器映射和节奏。恢复通过不等于音乐质量或训练适配性通过。
- 这套解析只针对六组管弦乐模型，并不会把这些文件自动加入主演奏页的旧四轨 R/H/B/M 模型。要训练旧模型，需要独立的 MIDI→四轨标注和格式转换及相应验证。
