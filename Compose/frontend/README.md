## 2026-10-01：乐器组角色状态栏

六组每行下方的状态栏显示正在演奏的小节里该组的角色（旋律 1/2/3…、和声、低音、节奏，可多项）。判断逻辑在 `src/roles.js`（纯函数，可单独测试）；`src/session.js` 的 `roleView()` 取音频时钟所在小节的已排程音符并缓存结果；`src/app.js` 的 `renderRoles()` 只在内容变化时更新 DOM。只做显示，不改音符或排程。

这里是浏览器侧的工作区，可单独在编辑器中打开来优化 UI。

| 路径 | 内容 |
| --- | --- |
| `index.html`、`style.css` | 主演奏页结构与样式 |
| `src/app.js` | 主页面控件与交互；`src/` 其余文件是浏览器内的演奏、音频和模型调用 |
| `orchestra/` | 五模型试听页及旧联合模型管弦乐页面；仅包含浏览器代码 |
| `four-pillar/` | 四大件 v1 五分钟试训的独立受约束试听页；权重与生成都留在本机后端 |
| `qa/` | 浏览器内音频检查页 |
| `vendor/`、`media/` | 浏览器模型权重、词表、音源及来源说明；UI 改版时不要无意改动 |

从项目根目录运行 `npm start`，或在本目录运行 `npm start`；两个命令都启动同一套本地服务，默认地址为 <http://127.0.0.1:4187/>。端口已占用时可指定 `PORT=4188 npm start`。浏览器仍使用 `/`、`/orchestra/`、`/qa/` 原有网址，另有 `/four-pillar/` 试训试听页；`/api/orchestra/*` 和 `/api/four-pillar/*` 由相邻的 `backend/` 提供。

只调整视觉布局时，通常改 `index.html`、`style.css`、`src/app.js` 以及 `orchestra/` 的页面和样式。不要把后端的 Python 路径、检查点或训练语料复制进前端。主页面模型本来就在浏览器里运行，`vendor/` 仍属于前端运行资产，但来源检查点在根目录 `training/`，只保存一份。

主页现在只运行续训四轨主干 `training/runs/joint-continued-expression-v1/best-base.pt`，并保留同次训练的表现层与独立训练的六组分类器；原版权重保留历史备份，不再由主页加载。2026-09-29 的试听回归发现表现层的独立音高不稳定，目前由四轨主干决定可听音高，表现层辅助精确起音、时值、连音与力度，不让其原始音高反馈牵动和声。六组分类器可在页面上开关，关闭后按手动角色配器。UI 已移除旧场景面板，提供七种受训拍号。当前仍需用户试听验证；细节与后续任务见 [MODEL-INTEGRATION-ROADMAP.md](MODEL-INTEGRATION-ROADMAP.md)。

根目录的 `index.html`、`style.css`、`src`、`orchestra`、`qa`、`vendor`、`media` 是指向本目录的兼容软链接，不是另一份数据。前后端路径或音频调度改变后，在项目根目录运行 `npm test` 并做浏览器试听。
