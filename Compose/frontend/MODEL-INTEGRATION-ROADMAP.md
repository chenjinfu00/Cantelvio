## 当前已接入

- 主演奏页 `/` 只加载 `joint-continued-weights.js`：选中的四轨 R→H→B→M 续训主干 `best-base.pt`。旧版 `joint-weights.js` 留在项目中作历史验证和备份，主页不再下载或切换它。原有场景面板及旧风格/摇摆选项已从 UI 移除；当前只用 Lieder 条件，其他风格等独立微调模型。
- `joint-expression-weights.js` 来自同一次最优步数（42,377）的 `best.pt`，导出时核对了主干配对。它独立预测音高、分数起音、时值、连音标签和力度；但 2026-09-29 试听发现独立音高不够可靠（最佳验证 `R.pitch=2.999`、`B.pitch=2.846`、`M.pitch=2.229`），把整组预测音直接替代四轨主干会形成奇怪声部。**目前页面采用安全混合播放**：H/R 生成和弦与伴奏攻击，B/M 生成低音和旋律音高，表现层只为相应结构音附加分数起音、时值、连音与力度；缺少表现事件时退回十六分格。原始表现层音符仍由 `exactNotes()` 保存供研究，但不会作为可听音高，也不反馈到四轨主干（`expressionFeedback=false`）。B/M 仍可写合理的和弦外音，未全局强迫和弦音。
- `joint-arranger-weights.js` 来自六组分类器 `training/runs/joint-continued-arrangement-v1/best.pt`（选中步数 202,600）。整小节的实际待播放音符完成后提前分类到木管、铜管、打击乐、竖琴/键盘、高/低弦乐；演奏时按用户的 On/Off、角色和固定/游走筛选。页面顶部和乐器面板内均有“六组配器模型”开关：关闭时六组改按手动角色分配，四轨和弦／低音／旋律不变。若六组都关闭，开关不会改变声音。它**只给已有音符分组，不创作新的管弦声部**。
- 拍号控件已开放 2/4、3/4、4/4、5/4、6/8、9/8、12/8，使用训练时对应的 meter ID、每小节十六分步数与复合拍强拍分组。和弦谱保持两排各四小节，标拍号，并在每小节底部用三行彩色短线表示 R/B/M 精确起音；圆点表示模型给出了非 `none` 连音标签。谱面还**不是五线谱**。
- 浏览器端与 PyTorch 的三个模块对照测试：四轨主干逐 logit，表现层全部字段头与非空 context 的主干特征，六组配器头。`tests/continued-integration.test.js` 覆盖七个公开拍号、精确播放时间和用户开关/角色约束。`npm test`、三个 `validation/check-chart-*.mjs` 应在改动后重跑。
- 本机浏览器确认过 6/8 选择、生成的谱面音符标记与 Play/Stop（无控制台错误）；这不是听感盲测，也未覆盖 Safari、移动设备或所有连音类别。

## 已知限制与建议优先级

1. **先听、再决定如何重训表现层。** 在相同开头/速度/乐器下试听 4/4、6/8、12/8、Melody 开关、六组开关和 Walk。记录音符密度、跨声部冲突、力度突变和长短音。当前混合播放是听感回归的防护，不代表表现层绝对音高已学好；若要恢复完全自主的精确音符生成，应重设计有和弦／声部／前一音条件的联合音高头，比较作品级自由生成，而不是简单取消防护。表现层字段独立预测，连音标签仍可能和分数起音／时值不一致；稀有三／五／六／七连音需单独验证。
2. **优化页面节奏可读性。** 目前只有起音短线，未画音符长度、休止、连音括号或谱面力度。可以在保持八小节和弦谱布局的前提下增加可缩放的节奏视图或紧凑工具提示，显示准确分数值与比例；需验证桌面、平板、手机触摸区和过密小节。复合拍中的长度标签目前按四分音符份额显示，未处处换算成附点四分拍。
3. **调度与音质压力测试。** 配器头在预测小节完成时运行，而不是音频边界/起音回调；在慢设备上量测最长生成片段、8 小节预读和长时间循环。`render.js` 把单音最长播放限制为 8 个四分音符，跨小节变速使用当前/下一个 BPM 的近似；在跨多个变速小节的延音上应改为准确分段排程，同时确保 Stop/Panic/未来编辑取消旧事件。`/qa/` 目前的老夹具未单独验证新表现层，需补一套新模型离线音频夹具和削波检查。
4. **配器模型能力边界。** MIDI 分类器对已生成的钢琴式 Lieder 音符做组归属；角色标签和游走并未在训练集中监督。只启用某一组时会在允许组内硬选择，不意味着模型认为那组一定合适。若目标是真正的管弦织体/新增对位声部，需设计有可信组/角色标注的新生成头及作品级验证，不能把当前分类器描述为生成式全管弦模型。
5. **保存与来源。** `ailegro.scenes.v1` 的旧场景数据与 `normalizeScene` 仍保留用于兼容，但旧场景按钮已移除；若要保存新配置，应设计明确的“当前演奏设置”持久化，不要复活未训练的旧风格面板。继续核对新增权重/夹具的 `VENDOR_MANIFEST.json` 与 `vendor/JOINT-MODEL-NOTICE.txt`；本机 MIDI 的逐文件授权尚未核实，仅供本地研究试听。
6. **下一轮力度与速度**见 `../training/PERFORMANCE-TEMPO-V2.md`。当前 Feel 仅将离散谱面力度映射为音符力度／响度，wedge 尚未成为连续渐强；当前 BPM 仍由用户固定，模型没有生成速度。后续训练应把 BPM 作为连续条件，并新增由模型建议的「速度固定／游走」，按乐句更新、提前排程且遵守用户范围；新标注尚未用于训练，网页不要提前展示成已学习能力。

## 修改时不可破坏的契约

- 四轨每步顺序 R→H→B→M；当前播放禁用原始表现层音符的反馈，以免不稳定音高牵动后续结构。研究性重新启用时，完整表现音符只能反馈到**下一步**。窗口重启、未来和弦编辑和参数变化后必须重新编码同一段上下文，已排程小节不可改。
- `Session.progress()` 提前准备六组分类。音频边界与可听起音回调不应新跑模型；若预读未就绪，不要让同步推理卡住播放。关闭组绝不能发声；固定/游走只在开启组与角色允许集合内选。
- 音符的 `sub` 是十六分步内分数位置，`dur` 已是四分音符单位，**不能再乘连音比例**。`ratio` 是谱面标签。没有已知力度时，不要伪称 MIDI velocity 是记谱力度。
- 旧主干、源 MIDI、检查点保留供回溯；不要覆盖网页权重或增加未约定实验。新导出必须同步更新 PyTorch 对照夹具、来源哈希和授权说明。
