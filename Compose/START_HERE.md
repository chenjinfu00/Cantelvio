现在可以只打开 [`frontend/`](frontend/README.md) 做 UI 优化：主页面、管弦乐页面、样式、浏览器模型和音源都在里面；[`backend/`](backend/README.md) 存放本地服务与生成接口。`training/` 和 `.venv-training/` 仍在项目根目录，由后端使用，没有复制大型语料或检查点。根目录原有的 `src/`、`vendor/` 等路径是指向前端的兼容软链接；原来的网址和根目录 `npm start` 保持不变，进入 `frontend/` 后也能运行 `npm start`。

## 启动

需要 Node.js 20 或更新版本。在本文件所在目录打开终端：

```sh
npm start
```

浏览器打开 <http://127.0.0.1:4187/>。项目使用原生 JavaScript 和 Node 内置静态服务器，没有第三方 npm 依赖，无需 `npm install` 或构建。

主演奏页 `/` 现在只使用这一轮续训模型：四轨 R/H/B/M 主干、节奏／力度表现层，以及把已有音符分到六组的学习式配器分类器。试听发现表现层独立音高暂不稳定，当前由四轨主干决定可听音高，表现层只附加细节奏、时值与力度；不再把不稳定的原始音高反馈进和声生成。六组分类器有独立开关，关闭后按手动角色配器；六组都关闭时，开关不会改变原始声部。旧主干只保留文件作历史对照，不再由主页加载。场景面板已移除，未来其他风格拟采用独立微调。当前仍需用户试听验证，交接待办见 [frontend/MODEL-INTEGRATION-ROADMAP.md](frontend/MODEL-INTEGRATION-ROADMAP.md)。

另有 <http://127.0.0.1:4187/orchestra/> 管弦乐试听页：选择五组已训练模型之一，用相同参数生成 4/8/16 小节，试听简化合成音色、查看音符图并下载 MIDI/WAV。此页调用本机 `.venv-training` 和 `training/orchestra/work/runs/` 下的检查点；新生成的样本缓存在 iCloud 同步的 `training/orchestra/work/samples/`。它不会替换主演奏页使用的联合模型。合成试听不代表最终真实管弦乐音色；源 MIDI 单曲授权尚不明确，当前仅用于研究／个人试听。

试听页也可点击“开始连续演奏”：每次续写四小节，保留前文的模型上下文和随机状态，并提前准备下一段；两排各四小节的图表显示从音符推测的和弦（不是模型直接输出的和声轨）。可随时调整六组乐器的组合、速度、音高温度和 top-p，后续片段生效；换模型或种子则开始新曲。乐器组的“开启”表示允许模型使用，不保证每小节都会发声；“关闭”会排除该组。续写状态位于 `training/orchestra/work/sessions/`，与生成样本一起处于 iCloud 同步路径。

另有 <http://127.0.0.1:4187/four-pillar/> 供试听新四大件 v1 的五分钟试训权重。它从五首内部验证谱中选一首，以已完成的两小节提示、沿用前一小节的节奏和时值骨架，再由新检查点选择后两小节的声部与音高；可在已对齐的艺术歌曲上切换冻结旧四轨先验，以相同种子比较。这个受约束试听**不是**完整自由乐谱解码，也不是正式全语料训练的听感证据。只有第一段生成小节能使用来源核验的旧模型先验；开关两侧都保留已移植的部分旧权重。此页使用本机 Python 和原位检查点，不更换主页权重。

若端口被另一份演示占用，在 macOS/Linux 使用：

```sh
PORT=4188 npm start
```

然后访问 <http://127.0.0.1:4188/>。Windows PowerShell 可先设置 `$env:PORT=4188`，再运行 `npm start`。默认只监听本机。

播放器需要先点击 Play 才会启动声音。首次打开默认为 Hold、Every bar，乐器面板里的 Melody 为 Off；此后乐器面板会恢复本浏览器上次保存的选择。选择 **Auto + Free** 可让模型自己决定在哪一拍换和弦，把 Melody 切换为 On 可听到模型写的旋律。

## 当前已经能做什么

- 一个本地联合 Transformer（1,581,309 参数）按十六分音符逐步同时写出四条轨：伴奏节奏、和弦、低音、旋律。每一步的顺序固定为 节奏 → 和弦 → 低音 → 旋律。
- 主页面只展示 Lieder（艺术歌曲）条件与可选音色；旧的合成风格和四个场景按钮已从 UI 移除。旧场景数据格式与迁移代码保留，不作新风格的训练成果宣传。
- 主页面的“乐器与角色”统一管理原有的和弦、低音、旋律乐器，以及木管、铜管、打击乐、竖琴／键盘、高音弦乐、低音弦乐六组。每组可单独开关、选择和声／低音／旋律／节奏角色、设音量，并决定它保持固定还是参与配器游走。配器总按钮只有“固定／游走”：固定时所有开启组都演奏；游走时，标为游走的开启组按角色每隔 1/2/4/8/16/32 小节轮换，标为固定的组仍持续演奏。配置保存在当前浏览器。默认六组管弦乐与旋律关闭，原版声音不变。
- Hold 保持当前和弦（节奏、低音、旋律继续）；Auto 自动推进。Every bar 每小节换一个新和弦；Free 由模型在拍点上决定何时换和弦，一个和弦最长两小节。
- 和声温度、旋律温度只改变“选哪个和弦/哪个音”，不改变事件发生的频率；密度调节出新音的倾向。
- 固定主调或调性游走（每 4/8/16/32 小节换到相邻调，模型按新的局部调继续写）。
- 两行共八小节和弦谱，显示的就是模型已经写好、之后要播放的小节。上排播完，下排上移，补出后四小节；和弦宽度对应实际拍数。
- 点击未排程的未来和弦，可看到模型在该处最可能的和弦，也可自选根音、类型、转位；之前的小节不变，其后的节奏、低音、旋律与和弦重新生成。
- 英文默认界面，中英文切换；桌面、平板布局与手机横向谱面跟随。
- 本地声音检查页 `/qa/` 可生成可复现的测试 WAV。

主演奏页的六组分类器是这次 `joint-continued-arrangement-v1` 检查点，不是此前的五组管弦乐消融模型；它只给表现层已有的音符分组，不生成新的管弦对位声部。用户的角色与固定／游走仍是播放时硬约束。旧联合模型在训练编码上对十二平均律整体移调等变，不能把重复移调窗口误称为有效新训练。

这是独立音乐控制台，主界面没有 Tonnetz 键盘。

自动伴奏及模型的后续工作统一在本项目进行。`Tonnetz` 和 `Volta` 是旁边两个同级项目：前者保留键盘/和声可视化和现有功能，后者负责读谱翻页。

## 交接时需要知道

1. `README.md` 和实际实现描述当前状态。`PREPARATION.md`、`SOURCE_BASELINE.json` 是早期设计与来源快照，不应当作新的待办要求。

3. 谱面上的和弦就是之后要播放的和弦；已经排程或发声的小节不会被重新抽样。编辑未来和弦会保留之前的全部内容，只重写其后部分。
4. 温度、密度、Hold/Every bar/Free、音域限制与编辑约束是作用在模型输出分布上的采样规则，不是重新训练的结果。这是小型实验模型，测试通过不代表音乐质量。
5. 浏览器自己保存的场景不在项目文件里。旧版本保存的场景仍可读取：音色、温度、表现力与音量沿用，旧的和声风格、三拍子、摇摆节奏会转换成新设置。
6. 完整训练入口、原始乐谱压缩包、处理后的语料、参数检查点与评估脚本已集中在 `training/`。先读 [training/README.md](training/README.md) 与 [training/JOINT-MODEL-DESIGN.md](training/JOINT-MODEL-DESIGN.md)。主演奏页不依赖训练环境；管弦乐试听页需要本机 `.venv-training`。
