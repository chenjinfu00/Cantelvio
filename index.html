    新建或打开

    输入与编辑

  4. 04

    保存或导出

    保存为可编辑的 .cantel 文件，或从导出菜单生成 PDF、SVG 和 MIDI。

查看并复制详细提示词

把方括号里的位置换成你的文件夹，发给有文件访问权限的 Agent。

请帮我建立一个供 Cantelvio Stage 使用的曲谱库。 来源文件夹：[填写路径]；新曲库位置：[填写路径]。先检查文件并提出方案，未经确认不要移动、覆盖或删除原文件；如已有 Stage 谱库，先完整备份，包括曲谱库数据与批注，在副本上处理。 1. 清点 PDF 和同目录的 MIDI，计算 PDF 的完整 SHA-256。相同内容只登记一次，保留所有原文件及来源记录；不同内容的版本不要合并。 2. 建议“书架大类 / 小栏目 / 作品 / 版本.pdf”的目录。古典作品的书架使用简短且不歧义的常用名，例如“肖邦”“巴赫”“贝多芬”，不要把全名放在显示或文件夹名称里；游戏作品用系列名作书架。如常用名有歧义，用足够区分的名称，不确定则待核对。catalog 的 composer 仍记录统一的标准全名，以便 Stage 正确分类：肖邦为“弗雷德里克·肖邦”，巴赫为“约翰·塞巴斯蒂安·巴赫”，贝多芬为“路德维希·范·贝多芬”。小栏目按作品类型或系列中的地区划分。肖邦的圆舞曲、波兰舞曲等归“舞曲”，练习曲归“练习曲与复调”，夜曲归“抒情小品”。一首作品的不同版本放同一作品文件夹，相关 MIDI 放在旁边。PDF 文件名使用“版本 · 哈希前8位.pdf”，无版本名时用作品名。保留作品号、调性、乐章和重要副标题，不把同名不同作品合并。 3. 根据文件名、已有资料和谱面整理曲名、作曲家、版本、编曲、风格、年代及适用的地区（如原神的“璃月”写入 region）。风格与文件夹小栏目分别记录；区分真实作曲家和系列名称；同一作曲家的名称必须统一。对原神作品，title 使用“原神 - 作品名”，composer 填有证据的真实作曲家，region 只填写用户提供的目录或对应文件中明确写出的地区，并在报告注明原文及来源；无法指出这些直接证据时，即使依据常识认为知道地区，也必须留空、归入“地区待核对”。不同语言的作曲家署名只有在输入材料明确证明对应关系时才能统一，否则保留原署名并标记待核对。不要猜测。列出归类和重命名清单，等我确认后复制到新曲库。 4. 将两个文件都写在曲谱库根目录的“曲谱库数据”文件夹中，路径必须分别为“曲谱库数据/catalog.json”和“曲谱库数据/manifest.json”：catalog 顶层为 version: 1、localLibrary: true、items 数组；manifest 顶层为 version: 1、files 对象。每份 PDF 一条记录，以完整 SHA-256 为 id 和 sourceId；catalog 记录 title、composer、edition（如有）、arranger（如有）、style、era、region（适用时）、libraryFolder（书架名）、format: “pdf”、available: true、bytes、aliases；manifest 的 files 将完整 SHA-256 映射到相对于曲库根目录的 PDF 路径。同作品各版本的曲名和作曲家保持一致，版本差异放在 edition。新路径放 aliases 第一项，并保留原名；libraryFolder 填简短的书架目录名。整理报告和分类预览也使用简短名称，并附一份短名与标准全名的对照表。未知资料不要编造。保留已有目录中尚需使用的其他字段、记录和批注，避免重建覆盖旧库。 5. 统一命名：同曲各版本使用同一 title；保留来源明确写出的作品号、调性和乐章，不凭常识补写。只有能确认是同一作品、同一乐章或同一阶段时才合并：若一份写有 Phase、乐章或编号，另一份没有，暂分开并标为待核对，避免误合并。 edition 一律只从原始文件名提取，不从谱面额外加入编制、版本或改编者。仅使用文件名中括号里的版本说明、明确的“- 总谱”后缀、“_simple”标记，或明确出现的出版社与校订者名称；分别对应括号原文、总谱、简化版，或者按原文顺序记录出版社和校订者，例如“Peters_Czerny”写为“Peters · Czerny”。无这些明确标记则省略 edition，不把作品名当版本名。括号中的“·”统一改成“ · ”，并把“编曲：”后的人名保留为“编曲：姓名”；所有标记按原有顺序排列，不加入其他词。若文件名与谱面冲突，edition 固定为“版本待核对”，不要附加其他标签；谱面发现的改编者单独填 arranger，并在报告中说明证据。重复文件选择包含版本信息的原名；如有多个，按文件名排序选择第一个，保留全部原名。 6. 检查每个路径和哈希、重复项、作品与版本分组，以及大类和小栏目。Stage 会根据曲名和资料计算部分分组，文件夹层级不保证完全决定显示结果；报告不确定项和需在 App 中核对的分组。告诉我在 Stage 的「曲谱库」中选择哪个根文件夹，并提示我抽查曲目、版本和 MIDI。
